# RESEARCH — 归档资产与关联对象处理（T-1878）

> 目的：快照 HTML、引述块、闪卡、AV 行、打卡事件、外部回链、孤儿账本在**归档移动/两级删除**时的孤儿与反向引用风险，形成"跟随/保留/提示清理/禁止删除"的产品规则。
> 结论日期：2026-10-01。证据来源：本仓代码实证 + 隔离内核 spike（lifecycle-spike 8/8）+ s1-flow 生命周期矩阵。契约基座：D-0032/D-0033、DATA-CONTRACT §7。

## 1. 对象级结论表

| 对象 | 存储位置 | 归档移动（同笔记本） | 彻底删除 | 规则 |
|---|---|---|---|---|
| `custom-clip-*` 属性 | 根块 IAL | **跟随**（ID 不变） | 随文档消失 | §7.2/§7.3，无动作 |
| 用户标签（IAL.tags） | 根块 IAL | 跟随 | 随文档消失 | 同上 |

| 闪卡（riff） | 思源卡包按块 ID | 跟随（ID 不变） | 内核随块清理 | 无孤儿（内核语义） |

## 2. 关键实证

- **快照是笔记本级独立文件**：`snapshotAssetPath` 产出 `/{box}/assets/…`，与文档无引用关系（只有属性里存路径字符串）→ 彻底删除后成为**永久孤儿资产**（思源对 assets 无自动 GC）。量级可控（每篇一个 HTML），由用户在文件树手动清理；不做自动清理（D-0008 平静原则同源）。
- **宿主删除=递归删除连带子文档**（T-1877b）：用户删【归档】宿主 → 全部归档文章（含其快照引用属性）一起消失，但快照 **assets 文件仍留存**（独立文件语义）→ 这是快照孤儿的主要产生路径。已在 §7.6 回写，T-1879 发布材料须显著提示。
- **getBlockAttrs 对已删块返回 code=0+空对象**（T-1868）：任何"判存在"逻辑必须走 SQL；本轮修复的孤儿账本无限重试即源于此。

## 3. 本轮修复（随研究落地）

- `retryImportOrphans` / `retryInboxOrphans`：重试前 SQL 判文档存在，已删文档的账本条目计入 `expired` 并移除（不再无限重试）；UI 反馈追加失效计数。
- 顺带修复**既有 UI 缺陷**：`import.orphansRetried`/`inbox.orphansRetried` 的条件表达式模板在 `t()` 中从不求值（真机显示字面 `${skip > 0 ? …}`）——模板改纯占位符，条件拼接移到调用处（新增 `msg.remainSuffix`/`msg.expiredSuffix` 双语键）。
- E2E：T-1878 断言（建文档→入账本→删除→重试 → expired=1、账本清空）。
