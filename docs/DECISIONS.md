## D-0001（2026-09-29）属性规范定案：文章状态全部写入文档属性（根块 IAL）

一切文章状态（状态机/评分/摘要/重浮记录）写入 `custom-clip-*` 文档属性——思源内核数据。

完整字段表见 `docs/DATA-CONTRACT.md` §1；改动需新决策 + 迁移脚本。

## D-0010（2026-09-29）技术栈与工程范式照搬小驴人脉（源码定调）

**定调结论：采用人脉方案（Vite + Svelte 5 + TypeScript + pnpm，CJS 单文件输出），不采用 webpack（打卡/雷切）或无框架样板。**

4. `kernel/model/plugin.go:274`——插件目录=`<workspace>/data/plugins/<name>/`，
   装载入口 `/api/petal/loadPetals`；`kernel.js`（goja 内核侧插件）为可选项，本插件不用（同 D-0003 思路）。
5. `kernel/model/plugin.go:296-363`——i18n 按 `Conf.Lang→en→zh-CN` 依次尝试 BCP47 与

   → `zh_CN.json + en_US.json` 双名合规且必须**各自全量**（只加载命中的那一份）。
6. `app/src/plugin/index.ts:606-645`——`addAgentCapability({name,description,inputSchema,outputSchema,handler})`
   注册为 `plugin/frontend/<插件名>/<工具名>`，与规划书一致；另发现 `getSecret/getVariable`
   （密钥与变量库，index.ts:568-587）可作未来扩展备用位，不改变"插件不自带 key"红线（D-0004）。

工程范式：api/ 层是唯一内核交互点，domain/ 纯函数层框架无关（architecture 守门测试）；

## D-0017（2026-09-29）S1 写入与恢复语义

S1 先保证既有路径真实可用：用户明确收录、改状态可完成缺失字段或覆盖原状态；迁移、AI 与自动扫描仍不得覆盖用户手填字段。仅有来源 URL 而没有有效状态的文档在索引中列为待确认候选；收录后才进入五态队列。

外部导入只对新建文档使用 `createDocWithMd` 的 `tags` 参数带入导出文件标签，并在首次收录时写入原收藏时间与来源状态。此举不建立对既有文档 `tags` 的覆写权。`custom-clip-time` 目前在三入口的来源不一致，S2 必须定义统一含义及存量迁移，现阶段统计不可称其为统一的“首次入库时间”。

导入执行阶段会重新读取 URL 索引并维护本批已创建 URL 集合，不能只相信预览时的 duplicate 标记；同一预览重复执行时应跳过已有 URL。

迁移任务在确认预览后持久化，每篇回填成功或失败均保存游标；暂停保留进度，失败行可重试。属性与索引发生半成功时，续跑先读属性并修复索引。查询失败必须在面板显示，不能伪装为空库。上述口径已写入 DATA-CONTRACT §0–3。

## D-0018（2026-09-29）扫描分页、跨笔记本标签与候选失效清理

迁移预览和索引对账统一扫描三类范围：全库带剪藏状态或来源 URL 的文档、设置中指定的锚点笔记本、任意笔记本带 `#剪藏` 标签的文档。三类查询按 `updated DESC, id DESC` 使用 `LIMIT/OFFSET` 分页，合并时按文档 ID 去重；跨笔记本的 `#剪藏` 旧文也进入迁移预览。

对账只有在三类范围全部分页成功后才允许清理索引中的失效候选（文档删除、属性/标签消失或移出扫描范围）；任一页失败时保留旧索引并报告错误。全库状态/URL 次锚点独立保留已收录文章，文章移出锚点笔记本不影响其队列记录。候选来源证据和内部文档排除规则由 S2 的另项决策补充。

## D-0019（2026-09-29）候选凭来源证据入列，用户误报判定持久化

锚点笔记本、SQL 标签查询和属性次锚点只圈定扫描范围；它们不自动证明每篇文档是文章。未带有效五态状态的文档，须有有效 http(s) 来源 URL 属性、根块完整 `剪藏` 标签、或正文前十行的高置信独立来源行之一才进入待确认候选。普通正文行内链接不够；`剪藏技巧` 等长标签不能通过 `LIKE` 模糊命中冒充精确标签。候选索引保存 URL/站点、证据类型和缺失项供用户确认，且不计入五态队列。

用户点“不是文章”时经 clip-store 写文档属性 `custom-clip-excluded=true`，使索引重建后仍不反复提示；用户显式收录可清除该标记。新生成的周报、数据库和闪卡宿主写 `custom-clip-internal=true`；旧宿主以固定路径或标题回退识别。内部排除只作用于未收录候选，已有有效状态的文档仍按属性展示，以免误伤用户的同名文章。无来源的本地文档只能由用户显式收录，扫描不能自动认定。

## D-0020（2026-09-29）收录元数据与 URL 比较键统一

S2 为收录管线补充 `custom-clip-content-type`（`fulltext`/`link`/`local`）和 `custom-clip-time-source`（`source`/`document`/`capture`/`legacy`）。`custom-clip-words`/`custom-clip-minutes` 只从入口取得的 Markdown 正文计算，排除标题、来源链接和导入提示；链接条目明确为 `link`、0 字/0 分钟，缺字段仍显示未知。显式文档收录入口统一先调用 `captureDocument` 导出 Markdown，再交给 `captureClip`；导入、收集箱和迁移等已有正文的入口直接传入 Markdown。`captureClip` 本身不暗中导出正文；属性已有值继续受数据主权保护。

`custom-clip-time` 表示待阅读等待时间的基准：外部来源时间优先，其次文档 ID 创建时间估计，最后首次收录操作时刻；已有非空值永不重写，旧值缺来源在读取时视为 `legacy`。所有 URL 去重统一调用 `domain/url.ts` 的 `normalizeUrl`（仅 http(s)，协议/主机小写，移除默认端口、fragment、非根路径尾斜杠，保留 query 与路径大小写）；比较键只用于查重，不反写用户原始 URL。

## D-0021（2026-09-29）开始阅读与读完分成两个明确动作

今日拾遗的主动作“开始阅读”只把文章状态写为 `reading` 并打开文档；打开标题不推断已读，今日卡片也不直接写 `done`。用户在读库中明确执行“标记已读”后才进入 `done`，打卡桥也在这个完成动作上触发。这样“看过入口”“正在阅读”和“完成阅读”不会混成一个状态，归档仍保留完成历史语义，后续完成时间字段按 S3–S4 契约补齐。

## D-0022（2026-09-29）Folo/RSS 借鉴边界

参照 [docs/RESEARCH-folo.md](RESEARCH-folo.md) 吸收统一时间线、载体徽章、来源筛选、首次来源说明和可关闭的 AI 阅读辅助；不引入 Folo 的云端订阅、账号同步、社交集合、付费墙、RSS 订阅或自动代读。所有新增功能仍以思源文档属性为唯一事实源，并在实现、隔离验证、真机验收三态完成后才写入 README 的能力承诺。

## D-0023（2026-09-29）显式收录的 URL 冲突处理

统一收录管线在写入来源 URL 前按 `domain/url.ts` 的比较键完整扫描已有 `custom-clip-url`。同 URL 默认返回冲突文档并停止本次收录，界面提供打开已有文章的路径；只有用户明确选择保留第二份时才允许继续。这样导入、收集箱、候选和右键入口不会静默制造重复文章。显式收录可以同时解除用户此前写入的 `custom-clip-excluded=true`，自动扫描和迁移仍不解除该标记。

## D-0024（2026-09-29）阅读载体决定导航目标，打开来源不改变阅读状态

`custom-clip-content-type` 只允许 `fulltext`、`link`、`local` 三种已确认载体；缺字段或非法值在界面显示为未知，不凭字数 0 推断。全文与本地文档优先用思源 `openTab({doc:{id}})` 打开；仅链接条目在来源 URL 通过 `normalizeUrl` 的 `http(s)` 校验后提供“打开原文”动作，来源缺失时显示提示且不显示网页按钮。思源公开 `openTab` 没有外部 URL 目标，因此来源动作使用用户点击时的标准 `window.open`，不新增臆造内核端点。任何打开文档、原文或快照的动作均不改五态；用户必须显式执行“标记已读”才进入 `done`。

## D-0025（2026-09-29）统一阅读时间线筛选与排序

Dock、工作台和看板的阅读列表必须共用 `domain/library-view.ts` 的纯筛选/排序结果。筛选维度包括五态、站点、文档根块用户标签、收录来源、时间来源、内容载体和关键词；排序包括收录时间、更新时间、字数、优先级、评分和标题，并提供升降序切换。用户标签只读 `IAL.tags`，与 `custom-clip-ai-tags` 分开；筛选、分面计数和排序不得写属性或改变状态。候选只在 `inbox` 待确认视图显式加入，看板对同一投影按五态分列。索引中新增的 `tags`/`src` 只是可重建缓存，旧索引缺字段时按空值兼容。

## D-0026（2026-09-29）全文来源作为次级导航，主阅读仍打开思源正文

为对齐 Readwise Reader 的正文/原文切换调研（`docs/RESEARCH-reading.md` §3.2），全文剪藏在 `custom-clip-url` 通过 `normalizeUrl` 校验时可显示“打开原文”次级动作；这不改变全文主动作，主动作始终打开思源文档。仅链接条目仍以来源网页作为主动作；本地文档和未知载体不显示网页动作。来源动作只导航，不写状态；`domain/carrier.ts` 负责统一校验来源地址与主打开目标，UI 不得按载体自行复制判断。

## D-0027（2026-09-29）阅读上下文依附原生编辑器，当前属性优先

S3 聚焦阅读不渲染第二份正文。插件监听思源公开的编辑器加载、切换和销毁事件，仅在有有效读库状态的文档上，于 `IProtyle.element` 的正文之外挂一条可卸载的上下文：标题、载体、来源和当前状态，并提供显式完成、返回读库与来源动作。每次加载与属性变更从文档根块重读属性，状态写入仍经 `clip-store`；异步回读按请求序号丢弃过期结果，卸载后不再回写组件状态；切换文档或销毁编辑器清除旧上下文，避免把上一篇的状态显示在下一篇。`custom-clip-words` 仅用于提示“已标记全文但未记录正文长度”，不推断载体或生成伪进度。会话内最近阅读文档 ID 可供继续阅读，但不写插件存储或文章属性；重启后以 `reading` 队列回到文档。移动端编辑器事件与布局需在作者真机核验，失效时移动工作台的文档入口仍可使用。
