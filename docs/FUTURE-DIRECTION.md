## 定位与服务对象

**管理思源里已经保存的文章，帮助用户做阅读取舍、持续阅读，并在需要时找回原文与摘录。**

这延续 D-0016 的“可信待阅读清单、重新打开、读完或放下”。插件的特色应体现在文章存下之后：知道哪些值得读、此刻适合读哪篇、中断后能接着读、读过的内容能再次派上用场。思源承担正文编辑、块引用和同步；拾遗承担文章的阅读生命周期及相应入口。

优先服务三类场景：

- 存量文章很多、经常找不到下一篇的用户，需要可信读库与有节制的重浮。
- 阅读时间零散、经常中断的用户，需要轻量选文和可靠的继续阅读。
- 已经在思源做摘录和笔记的用户，需要从记忆线索找回文章，并保留来源地复用。

采用这条产品链评估后续需求：**可信收录 → 做取舍 → 选一篇 → 接着读 → 明确读完或放下 → 找回与复用**。新需求应能指出改善其中哪一步、用什么真实任务验收。

## 方向一：可信主链与清楚的入口（P0）

近期首先关闭现有用户路径的证据差额：用少量真实文章走通发现候选、确认收录、分拣、打开、完成或归档、再次找回；验证写入失败和“属性已写入、索引待同步”两种结果都能理解并恢复。

首页继续围绕“继续阅读、待确认、今日拾遗、最近收录”安排信息层级。这里描述用户任务，不新增四个一级页面；低频维护、导出和高级 AI 收到相应次级入口，遵循 T-3287 的收敛方向。桌面、窄 Dock 和移动端保持同一动作含义。

交付门槛：

- 普通笔记不会无依据进入读库，来源链接与本地全文的差异可见。
- 显式操作后，文章属性、当前画布和其他已打开画布的结果可核对。
- 失败保留当前上下文，能重试或进入明确的修复路径。
- 用户能区分打开、开始读、读完与归档；归档可以是正常的阅读取舍。

B-0002 等真实验收按功能逐项记录，局部问题局部关闭。作者尚未提供主宿主窗口期时，交互协议、样本整理和独立文档工作可以继续；隔离验证不能替代真实证据，也不必等待全部可选集成都完成后才推进独立改进。

## 方向二：按可用时间和主题选一篇（P1，优先新增）

以“我现在有 15 分钟，想读这个主题”为最小新场景。在已有今日拾遗和读库筛选之上，研究 5/15/30 分钟等可用时间选择，结合用户标签、预计阅读分钟、优先级与等待时间，给出少量候选及入选理由。

先复用现有元数据和确定性投影，明确区分“本次按条件挑选”和每日默认推荐。筛选本身不修改文章属性；无标签或预计时长的文章应显示未知并有可理解的处理方式。预计分钟不代表实际阅读分钟，缺少本地正文的链接条目不能伪装成可离线读完。

范围控制：

- 首个方案使用现有用户标签；AI 标签只可作为后续可选补充，不成为使用门槛。
- 当天置顶、换一篇、略过和归档复用已有动作；空结果应能放宽条件或返回原清单。
- 将未读选文与已读回看区分用途；重浮要可解释、可换掉，避免产生阅读欠债感。
- “指定日期再提醒”和长期调度需要新契约，当前“今天略过”不等于跨日预约。

交付门槛：从真实存量中，用户能选出一篇符合当前条件的文章，理解为何入选，并在不适合时调整选择。先确认元数据覆盖率足以支持场景，再决定是否需要新字段。

## 方向三：中断之后接着读（P1）

复用现有显式书签、最近阅读与前台计时，重点补齐“离开文章 → 回到原读库位置 → 继续同一篇”的往返体验。应先明确当前画布会话、Dock 重建和宿主页签重开的生命周期，分别决定保存何种最小界面状态。

原生思源页签继续作为可靠阅读入口，ReaderTab 依现有实验开关提供增强。恢复位置失效时应解释并回到文章，不把结构进度条或视口移动推断成读完。

自动断点、近似阅读百分比、跨设备合并和 TTS 续听为后续研究项；朗读位置与阅读书签的含义须分别定义。当前实例内串行队列、读回校验也不能扩写成跨客户端事务保证。

交付门槛：从筛选后的列表进入文章，留下书签，切换后返回时能理解当前位置并继续；删除或移动原块、切换文章和重建画布都有可说明的退路。

## 方向四：找回文章，并把摘录用起来（P1–P2）

优先连接已有读库检索、摘录聚合和阅读回顾，让用户从主题、标题片段、时间或摘录线索找到文章，知道命中了什么，并回到原文或确切块。全文检索范围及宿主能力必须先确认，不能把现有标题或摘要匹配称为全文检索。

复用现有标签和保存视图组织专题阅读，先验证是否足够；新建专门的项目、分类或知识管理系统收益较低。摘录整理稿与带回链导出已有实现，重点核验真实回跳、失效来源、重复整理与导出可读性。

“一句收获、我的观点、下一步行动”可以作为后续用户样本研究。若确有价值，优先承接到用户的普通思源笔记并保留出处；它是用户自己的产出，不自动生成完成事实，也不把笔记正文存进插件 saveData。

交付门槛：用户隔一段时间，凭一条记忆线索找回文章或摘录，并将选中内容用于自己的笔记，仍能追溯来源。

## 方向五：有依据的阅读 AI（P2）

先验收现有摘要、翻译和单篇问答：处理范围清楚，截断和失败可理解，逐字引文能够核验，保存前能审阅。现有单篇问答的引文校验不代表所有摘要与建议都已有块级引用。AI 默认关闭或手动，遵循现行通道与额度契约。

可借鉴外部插件的阶段反馈与可配置审阅视角，将较长任务分成可理解的阶段，让用户知道正在处理哪篇、哪一步、有哪些结果需确认。任务进度与取消语义必须符合实际能力；当前 SDK 无法中止已发出的内核请求，只能丢弃迟到响应。

跨文章、库级证据问答（T-3334）值得研究，服务于“以前存过哪篇、它说了什么、几篇之间有什么关系”。进入实现前须明确：

1. 检索范围限定为当前有效读库及用户选择的范围，区分标题、摘要与原文证据。
2. 依据绑定确切文档/块和本次正文版本或内容校验值；源内容变更或访问失败时重新核验。
3. 回答可以跳到出处，依据不足时说明不足，禁止把检索不到补成确定结论。
4. 复用既有通道、额度、隐私提示与人工确认；调用前能知道会发送哪些内容。

图片理解、OCR 和视觉清理排在后续：先确认正式内核契约与真实图片输入确实参与模型判断，再提供逐项建议。原文批量改写、删图或替换正文需另有事务与恢复实证。

## 与思源及其他插件的分工

| 边界 | 开发取向 |
|---|---|
| 剪藏与抓取 | 优先承接已有剪藏、四格式导入和收集箱，不新开 RSS/网页抓取服务产品线 |
| 正文与同步 | 依托思源文档、块和原生同步，不另存正文或建设插件云同步 |
| 属性与数据库 | `custom-clip-*` 经 clip-store 读写；AV 目前只承诺属性→状态列，其他列与反向同步另行研究 |
| 快照 | 当前是思源文章文档快照，保持这个语义；重新抓取网页属于另一能力 |
| 复习与习惯 | 先验证 riff、制卡与打卡公开桥，复用现有生态承接后续行动 |
| AI | 围绕选定文章与明确阅读任务，不扩展通用聊天窗，不自带 LLM key |

所有新文章字段和检查点先进入 DATA-CONTRACT；未知端点先 spike。自动推荐与 AI 不覆盖用户手填 URL/status/priority/rating，状态仍由用户明确操作。

## 分阶段推进与进入条件

| 阶段 | 首要交付 | 进入/完成条件 |
|---|---|---|
| A：当前收口 | T-3351/T-3352 对应的真实主链证据；独立推进下一切片协议与样本 | 按 B-0002 分项记录结果；可选能力继续按 B-0004–B-0008 独立验收 |
| B：阅读主线 | 按时间/主题选一篇；可靠返回与继续阅读 | 先选一个完整用户结果，明确失败路径；必要宿主契约和数据覆盖已确认 |
| C：阅读复用 | 文章/摘录检索衔接、专题视图、原块回跳和整理稿质量 | 先验证真实找回与复用任务，再决定是否扩展个人产出流程 |
| D：有据智能 | 现有 AI 质量收口后，研究库级证据问答 | 有可靠检索、原文依据校验、隐私/费用口径及真实模型样本 |

阶段表示依赖顺序，可按能力分项验收；不绑定版本号或机械地等待所有外部集成。真正开始功能实施时，将选中的最小范围写入当前执行板，并补契约、交互和验收依据。

**建议下一批只选择一个用户结果：“有 15 分钟时选到一篇，读到一半离开后能返回原列表并继续。”** 先产出交互与状态协议、元数据覆盖样本和失败场景；若宿主恢复契约暂时不明，将返回恢复拆成独立后续，不为整个场景臆造宿主路由。

该切片先不增加文章字段、通知系统或 AI 依赖；时间/标签筛选优先作为会话内状态。是否持久化筛选和滚动位置，按现有偏好契约与宿主生命周期研究结果决定。

## 用什么判断值得继续投入

先用真实任务建立基线，再给耗时、点击数或成功率设目标，不预写改善数字。可由人工试用记录采集，不新增隐式行为追踪或遥测。

| 任务 | 观察结果 |
|---|---|
| 首次收录 | 能识别来源和载体，明确确认，随后在读库找到 |
| 零散选文 | 能找到符合时间/主题的文章，理解未知数据与无命中情况 |
| 中断恢复 | 能返回文章与原筛选上下文，位置失效时知道如何继续 |
| 过后找回 | 能凭片段或主题找到原文/摘录，并理解命中原因 |
| 摘录复用 | 整理到笔记或导出后仍可追溯来源，重复与失败可处理 |
| 异常恢复 | 事实未丢失，明确区分文章写入结果与派生索引状态 |

功能数量、测试数量和连续完成天数只作辅助信息。打开次数不等于读完，读完不等于理解，归档不等于失败。
