# UI 专项质感与美观复核（2026-09）

## 范围与结论

本轮只读检查覆盖 `src/index.scss`、`src/ui/*.svelte`、`docs/UI-STANDARD.md` 与 `design/prototype.html`，重点看视觉层级、信息密度、组件一致性、响应式、主题降级、反馈状态和视觉回归。没有修改 `src/`，没有驱动作者真实思源窗口，也没有把静态判断写成真机验收结论。

当前基础已经具备品牌色、状态色、三档画布、卡片/行表/看板/阅读页签和迁移器等设计语言，但实现存在几类明显漂移：

1. 令牌与组件边界不够集中。`src/index.scss` 里仍有大量直接写入的 `rgba/#fff`、固定尺寸和渐变；设置、导入器、统计卡继续使用 inline style，导致主题、高对比和窄容器下难以统一调整。
2. 同一语义在不同画布的视觉权重不一致。头部、队列胶囊、rail、行操作、横幅和主按钮都能抢占注意力；部分行操作在正常状态长期展开，部分图标按钮只在 hover 出现，用户难以判断主次。
3. 关键场景的窄宽退化不足。阅读伴生栏固定 264px、看板固定五列、设置和导入器依赖固定宽度；现有根类判断不能覆盖任意 tab/浮窗尺寸。
4. 状态反馈的视觉协议还不完整。空态、加载、失败、部分成功、处理中、禁用和完成反馈的样式分散；进度条、统计图和候选横幅在数据异常或长文案下没有统一的可解释外观。
5. 主题、动效和可访问视觉守门仍需集中验收。已有任务覆盖焦点、减少动效和高对比，但尚未形成“令牌→原型→三画布截图→中英文长文→真机”的单一回归链。

## 设计约束

- 继续遵守 `AGENTS.md`、D-0011、D-0016、D-0029、D-0030：颜色以 b3 变量和已有 `glean-*` 令牌为事实源，类名保持 `glean-` 前缀，UI 不直接写内核端点。
- 本轮只登记任务；任何样式、组件或原型改动都要先点具体任务，并按“原型帧 → `src/index.scss` → 双语/主题/响应式 → 截图回归 → 真机”顺序推进。
- “更有质感”定义为层级清楚、密度可读、反馈完整、动效克制和主题稳定，不通过增加装饰、常驻光晕或更多渐变来堆视觉效果。
- 视觉验收要覆盖 Dock、Tab、独立浮窗三画布，浅色/深色、中文/英文、空/满/失败/处理中、鼠标/触控/键盘和 240–1200px 宽度范围。
