# Agent 开发主清单（UI v2 与产品主链）

> 用途：供 AI Agent 直接读取、认领、执行和验收的唯一当前开发清单。旧 `TODO.md` 保留历史账本；本文件只保留未完成、可执行、可验收任务。
>
> 当前基线：产品主线是“发现有来源证据的文章 → 用户确认收录 → 分拣 → 开始读/稍后读 → 明确读完 → 回顾”。原型基线为 `design/prototype-v2.html`，UI 规范为 `docs/UI-STANDARD.md §9`。
>
> 禁止触碰：版本号、CHANGELOG、README 徽章、`docs/PROGRESS.md`、`docs/ROADMAP.md`、`docs/HANDOFF.md`；不得承接 ROADMAP 的 T-1740–T-1827。若发现依赖这些文件，先在本清单记录阻塞，不得擅自修改。

## Agent 执行协议

> 任务主计划：本文件是当前可执行任务的归并入口；`TODO.md` 中 T-1833–T-3200 为历史来源和映射依据，不应再次逐条照搬。ROADMAP 的 T-1740–T-1827 明确排除。

1. 开始任务前读取 `AGENTS.md`、`docs/PRODUCT-REPLAN.md`、`docs/UI-STANDARD.md`、本文件和相关 `docs/DATA-CONTRACT.md`。
2. 一次只认领一个任务；先写明目标、涉及层、契约影响、验收样本和风险。
3. 涉及属性、端点、存储或 i18n 时，先更新允许修改的契约/决策文档，再改代码；不得臆造思源 API。
4. domain 禁止依赖 UI、API、services；UI 禁止直接 fetch；属性写入必须经过 `services/clip-store.ts`。
5. 新 UI 先更新 `design/prototype-v2.html` 对应帧，再 port 到 Svelte；类名使用 `glean-*`，颜色使用 b3 变量。
6. 每个任务必须具备：实现、失败路径、空态/加载态、i18n 中英文键、测试或可解释的手工验收。
7. 完成后运行与范围匹配的 `pnpm check`、`pnpm test`、必要的隔离 E2E；报告真实状态：实现完成、隔离验证通过、作者真机待验收。
8. 不得顺手扩展任务范围；发现新问题只追加到本文件“发现池”，不得偷偷修复。
9. 不得修改受保护文件；不得执行版本发布、打 tag、Release 或集市提交。

## 状态和优先级

- `TODO` 待开发；`DOING` 已认领；`BLOCKED` 外部条件未满足；`DONE` 完成并通过本任务验收；`VERIFY` 代码完成但等待隔离或真机验证。
- P0 = 主链阻断或数据风险；P1 = 主流程舒适度和可靠性；P2 = 增强功能；P3 = 远期探索。
- 每项任务必须同时写“依赖”和“完成定义”，不能只写功能名。
