# 阻塞与风险（BLOCKERS）

> v1.0.4 的核心用户流程存在内部 P0 断点，按 [PRODUCT-REPLAN.md](PRODUCT-REPLAN.md) S1 修复；它们不依赖作者输入。以下保留需真实环境或作者参与的验收项。新阻塞按 B-xxx 编号追加，解决后移入“已解除”。

## 活跃

- **B-0001** 官方剪藏扩展的实测产出核对（M0 spike 第 4 项）需要作者在真实浏览器装扩展实剪 3 个站。
  程序侧已按扩展源码 payload（`createDocWithMd` 带 tags + 模板正文链接行）模拟验证；
  实剪核对作为作者验收项后置（作者指示：需真人操作的往后放）。
- **B-0002** 作者真机/真内核 UI 验收：基础 addDock/addTab 呈现（M0 spike 第 5 项）以及当前 S3 的
  Dock、工作台、看板三画布同文档状态动作、载体徽章和打开目标；还需核对原生编辑器阅读上下文的挂载/切换/销毁、
  返回读库能定位原文、移动端可见按钮或动作 sheet、仅链接来源打开和本地文档不出现网页动作；
  S3 收尾新增：行表/看板/卡片的"正文待核"标记，阅读条"检测正文"与"重新剪藏"动作的实际观感，
  以及标记已读后统计页/周报完成时间口径是否符合直觉；
  S4 新增：今日拾遗"为什么出现"理由行、超龄候选清单勾选归档交互；
  阅读页签（D-0029/T-1730f）新增：`glean-reader` 页签挂载与 Protyle 渲染、同文档双实例（页签+原生）编辑实时同步、
  preview/wysiwyg 切换、页签关闭后内存释放、快捷键/IME 冲突、大文档滚动性能、设置开关开启后"开始阅读"入口路由；
  伴生栏（D-0030）新增：正文中选区后摘录段/翻译按钮的实时可用性、摘录引述块插入位置、制卡入口、
  真实模型下总结/翻译质量与结果卡复制/保存为 AI 摘要（并入 B-0004）、相关旧文点击页签内跳转；
  本轮新增：✨AI 标签筛选（筛选器/rail）与用户标签不混用、"✓→ 读完并下一篇"切页与队列空提示、
  7 个命令动作实际触发（标记已读/下一篇/稍后/归档/原文/摘录选区/帮助）、首启引导只读扫描预览步。
  代码层与隔离服务验证已落地，页签运行时行为受 B-0009 限制只能在真机验证，不能替代作者目视和移动端验收；UI 自动化仍受 B-0010 约束。
- **B-0003** 闪卡 V2（`registerFlashcardV2PluginType`）依赖内核 v3.8.6/v3.9 分支落地，时间不可控；
  摘录制卡先走 `riff/createCards` 现有端点，不阻塞任何里程碑。
- **B-0004** 真实 AI 模型验收：分别检查富化、语义查重、相关旧文、预置动作、智能体工具；
  自定义通道还需真实 OpenAI 兼容 API、思源密钥库与桌面端连接测试。内部自动队列缺陷先按 T-1704 修复。
- **B-0005** 用作者实际 Pocket/Omnivore/wallabag 导出文件验证解析、URL 去重、时间/状态映射和“仅链接条目”的阅读体验。
- **B-0006** 真机验证全页快照的拍摄、打开和资源可用性，确认它是“思源文档快照”而非原网页抓取。
- **B-0007** 思源收集箱联调需要可用的登录/订阅环境；验证迁入全文、云端删除失败后重试及去重。
- **B-0008** 小驴打卡双插件真机联调：项目选择、读完记录、同日去重与失败恢复；雷切接入仍待公开 API。
- **R-0001** `ial LIKE` 大库性能——spike T-1005 实测定方案，上限兜底=saveData 索引。
- **R-0002** AI 不可用/用户未配置——全链路静默降级 + 功能矩阵测试锁死（M3 验收项）。
- **R-0003** 名称「拾遗」不含功能词，集市检索弱——README/描述/标签三处关键词补偿（剪藏/稍后读/阅读管理/收件箱/文章库/读库）。

- **B-0009** UI 自动化冒烟受环境限制：桌面版 stage 构建含 electron 外部引用，
  纯浏览器无法启动思源前端（详见 docs/RESEARCH-browser-e2e.md）。启动器已落地
  （scripts/e2e/launch-e2e.mjs，隔离工作区+真实 dist+演示数据），可用桌面客户端访问；
  Electron 自动化（Playwright+Electron，人脉有先例）待作者需要时投入。

- **B-0010（安全警示， 结论：UI 冒烟交由作者真机执行）**：尝试 computer-use 驱动真机桌面客户端做
  UI 冒烟时发现两个风险：①思源桌面端有单实例转发机制——带 --workspace 启动第二实例时参数被
  转发给已运行实例（新进程无窗口无内核，成为孤儿，已清理）；②computer-use 绑定应用名会命中
  作者正在使用的真实实例窗口。处理：发现后立即停止一切交互（仅做过被动截图，未向作者窗口
  发送任何点击/键盘），孤儿进程已清理，作者主实例经 6806 探测健康无损。
  **结论：UI 冒烟不使用 computer-use 远程驱动**，由作者在真机直接执行（B-0002 清单），
  或作者明确关闭常驻实例的窗口期内另行安排。
