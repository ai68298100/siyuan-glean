# 情境选文协议（T-3362 / D-0241）

## 目的

情境选文回答“我现在有一段时间，想读某个主题，哪一篇最合适”。它是一次会话内的确定性投影，与每日拾遗的 `pickDaily`、`lastSurfaced` 和随机稳定选择分开。应用筛选只读现有索引，不写 `custom-clip-*`、`saveData`、`lastSurfaced` 或阅读状态；用户点击开始阅读后才复用既有打开与状态动作。

## 输入与边界

- 时间预算只有 5、15、30 分钟。`minutes` 是预计阅读分钟，不代表真实阅读累计分钟。
- 默认候选状态为 `inbox`、`later`；`done` 只有用户显式开启“回看已读”才进入。
- 候选、内部宿主和显式排除条目始终排除。
- 主题只精确匹配根块用户 `tags`，大小写归一；`aiTags` 只可展示，不能成为主题门槛。
- `contentType=link` 可以进入结果，但必须带“只能打开原文、不能保证离线读完”的理由。
- `minutes` 缺失、为 0 或非法时默认不进入预算结果；用户明确放宽后可以进入，但带 `unknownMinutes` 理由，不能声称符合预算。
- `waitingDays` 由调用方根据可信入库时间计算；缺失按 0 参与排序，不写回文章。

## 排序与结果

结果最多返回 3 篇（调用方可将上限夹到 1–10）。排序依次按优先级降序、等待天数降序、预计分钟升序、文档 ID 字典序收尾；相同输入始终得到相同结果，函数不改变输入数组或标签数组。

每篇结果包含结构化理由：预算/未知时长、主题、优先级、等待天数和链接载体。UI 将理由映射为双语文案，不在域层拼接用户可见文本。无结果时应根据诊断提供放宽预算、清除主题或回到原清单；诊断至少区分无匹配、超过预算、未知分钟、主题不符、状态不符和被排除条目。

## 失败与退路

| 情况 | 结果 | 可操作退路 |
| --- | --- | --- |
| 没有预算内文章 | 空候选，保留统计诊断 | 放宽到更长预算、清除主题、回原清单 |
| 只有未知分钟 | 默认空候选；显式放宽才展示 | 允许用户查看未知时长，继续核对文章 |
| 只有链接载体 | 返回候选并标明只能打开原文 | 打开来源，不能承诺离线完成 |
| 主题无命中 | 空候选且 `tagMiss` 增加 | 清除主题或换标签 |
| 读取索引失败 | 由服务/UI 保留旧列表并提供重试 | 不生成空结果冒充“没有文章” |

本阶段只交付域层协议、样本和回归测试。真实宿主视觉、移动端、读屏和返回原列表/滚动位置的生命周期仍归 B-0002；不把隔离测试或原型结果写成真实验收。
