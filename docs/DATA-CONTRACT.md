# 数据契约（DATA-CONTRACT）

> 本文档是小驴拾遗"生产数据边界"的唯一事实源。改任何一条存储/字段约定，先改这里。
> 全部端点形状经 M0 spike 在思源 v3.8.5 真内核实证（`scripts/spike/`，报告见 `docs/spike-report.md`）。

## 0. 数据主权划分

| 数据 | 存放位置 | 插件卸载后 |
|---|---|---|
| 文章状态（五态/评分/优先级/摘要/AI标签/重浮记录） | 文档属性（根块 IAL，`custom-clip-*`） | **仍在**（思源内核数据） |
| 用户自己的标签 | 根块 IAL `tags`（官方剪藏写入位） | 仍在；外部导入仅在新建文档时带入文件标签，之后插件不覆写 |
| 派生索引 `glean-index.json` | 插件 saveData | 随插件删除，可随时重建 |
| 迁移任务进度 `migrate-progress.json` | 插件 saveData | 随插件删除；仅用于暂停、恢复与失败重试，文章属性仍是事实源 |
| 收集箱迁入检查点 `inbox-recovery.json` | 插件 saveData | 随插件删除；只用于防止已创建文档重复迁入 |
| 插件设置 | 插件 saveData | 随插件删除 |
| 排版整理稿 | 原笔记本中的独立普通文档，仅标记既有 internal | 正文与原文回链仍在；不复制原文读库属性 |

### 0.1 收录后自动快照（D-0117，T-3268/T-1798）

插件 `settings.json` 增加顶层 `snapshotOnCapture:boolean`，默认 `false`，只接受真实布尔值；设置页保存后才生效。所有统一收录入口在 `captureClip` 首次属性写入和派生索引同步成功后，按当前插件实例已保存的开关生成本地文档的 HTML 快照。不抓取来源网页，不调用 AI，不把正文保存到插件 saveData。

关闭开关、已有有效状态、URL 冲突、收录写入/索引失败或已有非空快照路径时不生成自动快照。快照继续沿用 `exportHTML → assets → clip-store.writeClip(custom-clip-snapshot)`，路径回写前核对原快照属性，避免覆盖期间由其他入口保存的快照。导出、资产写入、属性或快照索引同步失败只记不含正文/标题/URL/原始异常的阶段警告，收录仍返回成功；不回滚收录、不自动重试、不删除已写资产。用户可使用既有手动快照入口重试或检查资产。

备份包含规范化开关，恢复设置时强制关闭自动快照；需用户再次明确保存开启。真实 assets 显示、图片/链接保真、移动端及大文档体验仍按 B-0002/B-0006 验收。

## 1. 属性规范（文档级，根块 IAL）

`src/domain/schema.ts` 为唯一事实源；本表与其同步维护。

| 属性 | 类型 | 说明 |
|---|---|---|
| `custom-clip-url` | string | 来源 URL（收录时尽量回填；迁移启发式或手填） |
| `custom-clip-site` | string | 站点名（可空） |
| `custom-clip-author` | string | 来源作者/公众号/频道/专栏名称；用户可编辑，非 AI 标签；首尾空白去除，最多 120 个 Unicode 码点，单行且无控制字符；缺键表示未知 |
| `custom-clip-reading-position` | JSON string | D-0095版本1显式阅读书签 `{version:1,blockId,offset,at}`；合法块ID、块内像素偏移0–10000整数、UTC ISO时间；不是百分比或实读时长 |
| `custom-clip-time` | string | 待阅读等待时间的基准时刻 `YYYYMMDDHHmmss`（本地时区）：外部导入/收集箱优先原服务收藏时间；旧文回填使用文档 ID 创建时间作为估计；普通显式收录或无可用来源时使用首次收录时刻。与 `time-source` 一起解释，不把所有值称为“首次入库时间” |
| `custom-clip-time-source` | enum | `source`（原服务收藏时间） / `document`（文档 ID 创建时间估计） / `capture`（首次收录操作时刻） / `legacy`（历史值无可靠来源）。旧非空 time 不自动重写，缺来源时只在读取投影为 legacy |
| `custom-clip-status` | enum | `inbox` / `later` / `reading` / `done` / `archived`（D-0003 五态） |
| `custom-clip-done-time` | string | 完成时间 `YYYYMMDDHHmmss`（本地时区）：仅由用户显式“标记读完”动作写入，或导入时来自导出文件中的可靠已读时间（Pocket `time_read`）；离开 `done`（归档/恢复/重读）不抹除，再次显式标记读完时覆盖为最新时刻；缺键 = 完成时间未知（D-0028） |
| `custom-clip-content-type` | enum | `fulltext`（本地有正文） / `link`（仅来源链接） / `local`（用户明确加入的本地文档）；已有文档缺字段时显示“类型未确认”，不凭 0 字推定全文 |
| `custom-clip-words` | number | 本地正文字数：剥除标题、来源链接/元信息、代码与图片后按中英混排统计；仅链接为 0，缺键表示未统计 |
| `custom-clip-minutes` | number | 预计本地阅读分钟 = round(words/400)，有正文至少 1；仅链接为 0，缺键表示未知，界面不显示伪精确 0 分钟 |
| `custom-clip-read-minutes` | number | 用户真实前台阅读累计分钟；与预计 `custom-clip-minutes` 独立，按完整分钟落库，缺键表示尚未确认真实时长 |
| `custom-clip-priority` | number 1-5 | 手动优先级（重浮加权用，默认 3，用户手填字段） |
| `custom-clip-rating` | number 0-5 | 读后评分（可选，用户手填字段） |
| `custom-clip-ai-tags` | string | AI 标签（逗号分割，与用户 `tags` 完全隔离，永不覆盖用户 tags） |
| `custom-clip-summary` | string | AI 一句话摘要 |
| `custom-clip-last-surfaced` | string | 最近一次被重浮的日期 `YYYYMMDD` |
| `custom-clip-pinned` | string | 用户明确钉住今日拾遗的日期 `YYYYMMDD`；只在同一本地日历日置顶，次日自动失效但保留属性直到用户取消或下一次明确钉住 |
| `custom-clip-snapshot` | string | 单文件 HTML 快照的 assets 路径（T-1504，防内容/链接腐烂） |
| `custom-clip-src` | string | 来源管道：`web-clipper`/`inbox`/`manual`/`migration`/`import-*` |
| `custom-clip-excluded` | boolean | 用户明确判定“不是文章”的持久标记；`true` 时不再提示候选，用户显式收录可清除 |
| `custom-clip-internal` | boolean | 本插件自己生成的周报、数据库、闪卡宿主标记；仅排除未收录候选与迁移预览，不抹除已有有效状态的文章 |

写入规则：

1. 统一经 `services/clip-store.ts`（T-1100）读写，带 schema 校验与幂等；其余代码不得裸调 attr 端点写这些键。
2. 删除属性传 `null`（内核语义）。
3. 数字属性以字符串形态存入 IAL（内核 IAL 值均为字符串），读取时按 schema 还原类型。
4. 用户手填字段（`custom-clip-url` 已有值 / `custom-clip-status` / `custom-clip-priority` / `custom-clip-rating` / `custom-clip-author`）AI 富化与迁移器一律不覆盖；AI 只写 `custom-clip-ai-tags` / `custom-clip-summary`。已有非空 author（包括非法旧值）禁止自动覆盖或清空；显式编辑才允许定点覆盖/清除。
   D-0088补充：全部这些手填字段的默认保护也包括空字符串/null删除；只有明确force或仅限status的明确forceStatus才能删除原值，不把删除当作不覆盖。
5. 迁移幂等：已带 `custom-clip-url` 的文档整体跳过，不重写时间戳。
   只有 `custom-clip-status` 而缺 URL 的旧文属于待补全行：保留原状态，只回填来源与缺失元数据；执行期不能把它误判为已完成。
6. 面板、看板、命令中由用户明确发起的改状态可覆盖已有 `custom-clip-status`，必须以实际写入成功数反馈；扫描、迁移与 AI 的自动写入仍受第 4 条保护。外部导入的新建文档可以在首次收录时写入导出文件状态。
7. 仅有 `custom-clip-url` 而无有效状态的文档是待补全的半成品；显式收录须保留已有 URL，补齐状态等缺失字段。已有有效状态才视为收录幂等跳过。
8. `captureClip` 的收录元数据只消费入口已取得的 Markdown 或显式内容类型，不暗中额外导出 Markdown；收录成功后的可选 HTML 快照见 §0.1。手动、候选及右键入口统一经 `captureDocument` 先导出 Markdown；导入、收集箱和迁移入口传入已有 Markdown。`domain/content.ts` 只把明确 URL 或高置信模板/独立 URL 行当来源，普通行内链接不是来源；正文失败时可以收录但缺失项必须可见。导入器生成的元信息不计作全文，外部链接导入显式为 link。已有非空 time 一律保留；旧值无来源不自动写入 legacy，只作为读时投影。
9. 所有显式收录入口在写入前以 `normalizeUrl` 检查库内已有来源。发现同 URL 时默认不创建第二份，返回已有文档供界面打开核对；用户明确选择“仍保留第二份”后才允许写入。查重扫描分页未完整成功时必须报错并停止，不能以部分结果判定无冲突。用户显式收录同时可解除此前的 `custom-clip-excluded=true`。
10. `custom-clip-done-time` 只描述最近一次显式完成（D-0028）：`clip-store` 的显式状态动作把状态写成 `done` 时写入当前时刻；归档、恢复或重读都不删除旧值，`archived` 保留“读过”事实。旧数据、无已读时间的外部导入缺键即“完成时间未知”；聚合层（`domain/stats.ts`）的时间性统计（本周完成、周报列表）只按完成时间计，无完成时间的已读只计入状态总数，不得用文档 `updated` 或迁移当天伪造。正文测量（T-1727）只允许显式动作触发：导出正文后按 `domain/content.ts` 规则重算 `words/minutes` 并写回，不修改用户正文，不删除既有快照；“重新剪藏”是打开原文让用户用官方剪藏扩展重剪的显式导航，插件不静默覆盖文档内容。
11. `custom-clip-pinned` 只由用户显式的“钉住今日/取消钉住”动作经 `clip-store` 写入或删除，值必须是本地日期 `YYYYMMDD`；重浮挑选仅将等于今天的值排在普通候选之前，不改变状态、priority、last-surfaced 或每日数量。未行动文章次日自然回池，旧日期不再置顶但属性不被后台清理。

### URL 比较键（D-0020）

`domain/url.ts` 的 `normalizeUrl` 是所有文件内去重、预览/执行期库内去重与来源候选合并的唯一比较规则：只接受 http(s)，trim，规范协议和主机大小写，移除默认端口、fragment 与非根路径末尾斜杠，保留路径大小写与 query 的顺序和值。无效 URL 返回空比较键。比较键不反写 `custom-clip-url` 或用户正文，原始来源链接保持可见；语义相似不参与自动精确拒收。

## 1.1 阅读载体与打开策略（S3，T-1716/T-1722）

`custom-clip-content-type` 是阅读入口的唯一载体事实源；它不新增状态，也不因用户点击打开而改变五态：

| 载体 | 主打开动作 | 来源网页动作 | 缺失提示 |
|---|---|---|---|
| `fulltext` | `openTab({doc:{id}})` 打开思源正文 | 有效来源 URL 时可提供“打开原文”次级动作；不改变主打开目标 | 正文已在文档内，按属性展示全文徽章 |
| `link` | 优先提供“打开原文”来源网页动作；文档标题仍可打开思源链接说明 | 仅当 `custom-clip-url` 通过 `normalizeUrl` 校验为 `http(s)` 时显示；使用用户原始 URL，点击不写状态 | URL 缺失或非法时显示“来源链接缺失”，不渲染网页按钮 |
| `local` | `openTab({doc:{id}})` 打开思源本地文档 | 不显示网页按钮，即使文档正文中偶然存在链接 | 按属性展示本地文档徽章 |
| 未知/缺字段 | `openTab({doc:{id}})`，并展示“正文类型未知” | 不显示网页按钮，直到载体和 URL 由用户确认 | 保留未知徽章，不凭字数 0 推断类型 |

实现约束：思源 `openTab` 的公开类型只支持文档、资产、搜索、卡片和插件页签，没有外部 URL 目标；来源网页由用户点击时调用宿主浏览器标准 `window.open`。全文和仅链接载体可以在来源 URL 有效时提供来源网页动作，但全文的主动作始终是思源正文，仅链接的主动作才是来源网页；local/unknown 不显示网页动作。UI 必须先用 `domain/carrier.ts` 校验载体和 `normalizeUrl`，禁止拼接 `javascript:` 等非 `http(s)` 协议。打开文档、打开来源、打开快照均是阅读导航动作，不自动把 `inbox/later/reading` 改为 `done`；“标记已读”仍是独立显式动作。

## 1.2 来源作者（D-0085，T-3239）

author 只描述来源署名，不参与文章资格推断；普通笔记不能因只有作者属性进入候选或读库。读取非法旧值只在投影中留空，不修写原属性；显式写入非法值拒绝，不截断。清空用 author 空字符串经 clip-store 转为 null，必须是明确编辑动作。编辑先读取原始作者作为会话内比较值，提交时复查文档根块元数据、当前资格和原始作者；变化则保留草稿并要求重新读取，不用缓存覆盖。内核无原子 CAS，读写间外部并发仍无法保证原子排他。

同一插件实例对同一文档的作者编辑串行执行，每次排队后重新核对原始属性；不同文档不互相等待。写后读回再确认成功，失败或结果未知不自动重发；重新读取保留草稿并展示当前原始属性，让用户核对后再提交。跨插件实例/客户端仍受上述无 CAS 边界限制。

派生索引、库内作者筛选/关键词、独立作者 rail 与保存视图只投影该属性；候选不计作者分面。站点旁显示作者，可聚合该作者文章并按收录时间排列；移动筛选仍使用草稿/应用边界。属性 CSV 新增 author 列并沿用公式防护，匿名诊断不包含作者。首版只提供手动编辑，不调用模型、不回填作者真实存量；AI 推断另立默认关闭的建议/逐条确认流程，不能成为不受手填保护的自动写入。

## 2. 文章识别：双锚点

- **主锚点**：设置中指定的"读库笔记本"（可多个，存 `anchorNotebooks`）。
- **次锚点**：任意笔记本中带 `custom-clip-url` 的文档（SQL `ial LIKE '%custom-clip-url%'` 圈定，属性精确值走 attr 端点读）。
- 锚点笔记本 ID 必须作为 SQL 字符串字面量逐个引用并转义；任一范围查询失败须向界面报告，不能把失败结果呈现为“0 篇”。
- **辅助标签扫描**：当前版本扫描任意笔记本带 `#剪藏` 标签的文档，作为未收录候选来源；标签名目前固定为“剪藏”。SQL `LIKE` 只扩大扫描范围，最终由根块 `tags`/查询 `tag` 的精确 token 校验决定候选资格。
- **S2 候选资格**：扫描范围本身不构成文章证据。无有效五态状态的文档，须满足以下至少一种证据才进入待确认候选：有效的 http(s) `custom-clip-url` 属性；根块 `tags` 或 SQL `tag` 中完整的 `剪藏` 标签；文档正文前 10 行中的官方剪藏模板独立链接行（链接文本与目标均为同一 http(s) URL）或整行独立来源 URL。普通正文中的行内链接、含“剪藏”字样的长标签（如 `剪藏技巧`）、仅位于锚点笔记本中的普通笔记均不算候选。自动扫描只读属性与正文，不因发现候选写状态。
- **误报与内部文档**：用户明确标记“不是文章”时经 clip-store 写 `custom-clip-excluded=true`，后续扫描和迁移预览忽略该文档；用户显式收录时可解除此标记。插件生成的周报、数据库宿主与闪卡宿主经 clip-store 写 `custom-clip-internal=true`，旧文档按专用路径/标题回退识别。内部排除只用于未收录候选；已有有效状态的文档仍由属性次锚点展示，不因名称相似而被隐藏。
- **扫描分页与合并**：状态/来源次锚点、主锚点笔记本和 `#剪藏` 标签分别按 `updated DESC, id DESC` 分页查询，调用方必须读完所有页再合并，并按文档 ID 去重；迁移预览与索引对账使用同一合并范围。跨笔记本的 `#剪藏` 文档即使不在主锚点也能进入迁移预览。
- **导入 URL 查重**：外部文件预览与执行期均须读完状态/来源次锚点的全部分页，逐文档属性取 `custom-clip-url` 并按 §1 的比较键查重；任一分页失败即停止导入，不能把部分扫描结果当作无重复。执行期还应把本批已创建文档的 URL 放入查重集合。
- **导入失败恢复（D-0060，D-0093补充跨重载）**：完成页保留真实失败 URL 与已返回的文档 ID，仅重试失败行。已建文档但属性/索引失败时复用原文档，回读确认文档仍在且来源未被改写；已存在有效状态时只经 `clip-store.writeClip` 的空补丁同步派生索引，不重写五态、完成时间、手填字段、正文或 tags。完整 URL 查重只排除当前待恢复文档自身，其他同来源仍跳过。跨重载恢复使用下述派生检查点和重新选取原文件，不自动续跑。
- 正文启发式中只有前十行独立的官方模板 URL / 裸 URL 可作为候选证据；普通正文行内链接不得自动成为来源。
- **收录** = 首次写入全套 `custom-clip-*` 属性（status 缺省 `inbox`）。三入口：
  ①Dock 面板"新剪藏"区（锚点笔记本内无 `custom-clip-status` 的文档）；
  ②右键菜单"加入读库"（`open-menu-content`，任意文档可标记）；
  ③命令面板命令。

## 3. 派生索引（saveData，可重建）

`glean-index.json`：`clips` 仅保存有有效状态的收录文档的标题、路径、笔记本及状态、URL、站点、时间、完成时间、字数、分钟、
优先级、评分、重浮日期、摘要、快照路径、AI 标签、内容类型、时间来源和文档更新时间；`candidates` 保存未收录扫描候选的
ID、标题、路径、笔记本、更新时间、可解释的来源证据（URL 属性/精确标签/官方模板/独立来源行）、来源 URL/站点与缺失项（URL、状态）；URL-only 半成品属于候选。真相永远是文档属性；索引仅是可重建缓存。候选证据与缺失项是可重建投影，不作为独立写入数据。
当前更新时机 = 插件自身经 clip-store 写属性时 + 面板打开时对账；“重建索引”命令清空后重扫。对账只有在三类范围的**全部分页成功**后，才可依据完整扫描结果移除已删除、已失去候选资格或已移出扫描范围的候选；任一页失败时必须保留旧索引并报告失败，不能以部分结果清理条目。带有效状态或 URL 的文章由全库次锚点保留，不因移出主锚点笔记本而消失。
`migrate-progress.json` 在用户确认 dry-run 后建立，逐篇写入时保存 `rows/cursor/finished`。`finished` 仅表示本轮游标到尾，失败行仍保留供显式重试；暂停不得置完成或清除进度。重新执行失败行前先重读文章属性，已写成的文档只修复索引，不重复覆盖字段。
迁移预览中的逐行“补来源 / 本地文档 / 排除”只修改待执行计划；确认开始后才写属性。运行中不接受逐行编辑，避免与保存的游标和行状态竞态。执行前按 URL 比较键复查全库，冲突行留在 `manual`，记下已有文档 ID 供用户打开；用户明确选择“仍保留第二份”才写重复来源。游标已到尾但仍有 `manual` 或可重试错误时保留任务，重开迁移器仍能处理；`finished` 不代表所有行已解决。
S2 已加入完整分页与失效候选清理；索引仍是缓存，面板对账失败时保留上次结果并报告错误。

### 3.1 S3 阅读时间线视图投影（D-0025）

`glean-index.json` 的 `clips` 条目增加两个只读投影字段：`tags` 来自文档根块 IAL 的用户标签位 `tags`，`src` 来自 `custom-clip-src`。`tags` 不是 `custom-clip-*` 属性，插件只能在扫描/对账时读取并投影，不能为了筛选把用户标签复制、改写或清空；`aiTags` 仍单独保存并且不冒充用户标签。旧索引缺字段时按空数组/空字符串兼容，重建索引从属性和 IAL 恢复。

Dock、工作台和看板把同一批索引条目映射为 `domain/library-view.ts` 的纯函数输入，共用状态、站点、用户标签、收录来源、时间来源、内容载体和关键词筛选，以及时间/更新时间/字数/优先级/评分/标题排序。筛选、分面计数和排序只返回新的视图数组，不写入文章属性，不改变五态；看板在同一筛选结果上按状态分列。候选仅在“新剪藏/inbox”视图显式包含，不能混入其他状态。

三画布的队列配额、超龄候选清单和候选提示共用同一对账投影与显式动作（D-0068，T-3226），不因看板/行表/卡片布局分支遗漏。超龄仍只处理明确勾选的已确认文章，反馈实际成功数；未勾选、普通笔记与候选不会归档。

### 3.2 S3 原生编辑器阅读上下文（D-0027）

阅读上下文只在打开的文档根块有有效 `custom-clip-status` 时显示。每次编辑器加载或切换文档，以当前根块 ID 通过既有属性端点读取 `custom-clip-status`、`custom-clip-content-type`、`custom-clip-url` 和已有的 `custom-clip-words`，通过既有只读 SQL 查询根块标题；不以派生索引里的旧状态覆盖文档属性。`words` 只用于提示“已标记全文但未记录正文长度”，不据此推断载体或生成阅读进度。状态动作沿用 `clip-store`，成功后刷新上下文并通知读库视图，失败时保留原状态。来源按钮沿用 §1.1 的载体与 URL 校验，打开原文或返回读库均不写状态。

上下文条挂在思源公开编辑器事件所给的 `IProtyle.element` 内、正文之外；同一编辑器切换根块时卸载旧条，销毁编辑器时清理挂载。它不复制正文、不保存滚动或阅读百分比，也不在 `saveData` 留存上次阅读文档 ID。会话内可记住最近一篇已打开读库文章供“继续阅读”命令使用；重启后仍通过 `reading` 队列按文档 ID 返回。移动端原生编辑器挂载须作者真机验收，事件未触发时仍可从移动工作台按文档 ID 打开。

### 3.3 阅读页签（D-0029，T-1730）

阅读页签是**视图不是存储**：左侧为插件内嵌的真实思源编辑器实例（SDK `Protyle`，preview/wysiwyg 双模式），右侧伴生栏复用统一的属性读改服务。正文编辑、块级修改全部经该实例的内核事务落库，插件不另存正文副本；文章属性读写仍只经 `clip-store`，本节不新增任何文档属性。会话级状态只有"待打开的页签文档 ID"（内存变量，不落 `saveData`）。相关设置属插件设置（§0）：`reader.openInTab`（开始阅读是否在内嵌页签打开，默认 `false` 沿用原生页签）与 `reader.defaultMode`（`read`=preview 只读 / `edit`=wysiwyg 编辑，默认 `read`）。打开页签、切换模式、返回读库、打开原文均不写五态；右栏状态动作与三画布共用同一服务并按真实成功数反馈。选区摘录、批注与制卡进入页签伴生栏时按 T-1725 规则执行（块定位失败降级复制文本）；AI 伴读按 T-1726 与 D-0013 执行（手动、额度、静默降级、AI 来源标记）。移动端不提供页签。摘录与 AI 伴读的写入语义见 D-0030：摘录=引述块插入原文档（不新增属性，§4 自动聚合）；AI 结果临时显示，仅显式"保存为 AI 摘要"写既有 `custom-clip-summary`，额度与富化共享（`ai-usage.json`）。

选区摘录/复制/AI 动作仅消费正文宿主内的完整范围（D-0069，T-3227）：anchor、focus 和每个 Range 的起止节点均须在宿主内；任何跨宿主范围均拒绝，不因起点在正文就读取其他页面文本。可用块定位须是宿主内合法原生 ID，缺定位时仍保留仅复制降级，不伪造定位。

### 3.5 阅读外观与保存视图（D-0072，T-3230/T-3231）

`ui-prefs.json` 增加 `readerAppearance:{fontSize:'small'|'normal'|'large',lineHeight:'compact'|'normal'|'relaxed',width:'narrow'|'normal'|'wide',theme:'follow'|'paper'|'eye'}`（默认均 normal/follow）、`savedViews`（最多20项 `{id,name,filter,layout}`，过滤只保存已支持的 LibraryFilter 字段，layout=list/kanban）、`defaultSavedViewId`（默认空）和 `governanceMuted:{quota:string,stale:string,candidates:string}`（默认空，值只接受本地 `YYYY-MM-DD` 日期）。外观只作用于阅读页签宿主，不写全局主题、文章或跨设备进度；保存视图不保存正文、选择、候选资格、文档 ID 列表或计数；治理提醒按键记录“今天不再显示”的日期，跨日自动恢复，只影响界面展示。库列表的筛选、排序、计数仍基于完整派生索引，界面按固定窗口分批挂载并由用户显式加载更多，不改变索引、文章属性或选择语义。非法/未知字段丢弃，名称去空白、最多40字符、同名拒绝，ID 稳定且唯一，过滤与排序深拷贝。

阅读导航补充（D-0079，T-3233）：`ui-prefs.json` 增加 `readerSidebarCollapsed:boolean`，默认 false，只有布尔 true 才恢复收起；只隐藏伴生栏，不重建 Protyle，不存正文/选区/滚动位置。工具条在收起后仍提供模式切换、恢复伴生栏和快捷键帮助。快捷键只在本页签获得焦点且处于阅读模式时生效：j/k 滚动、e 切编辑、m 显式标记已读、x 摘录当前完整宿主选区、? 帮助；输入框、编辑区、菜单/弹窗、IME、组合修饰键和已处理事件不接管。只有滚动允许键盘重复，写动作仍受忙碌门禁和当前文章资格限制。切文/卸载使旧上下文请求失效，旧文章操作可以完成其原目标写入，但不能更新当前另一篇的展示、保存另一篇摘要或触发自动切文。

prefs 同一插件实例的读改写串行，避免多入口互相丢偏好。读取错误不伪装空设置继续写，保存失败保留草稿并反馈；载入失败不自动覆盖。使用默认视图前校验仍存在，删除默认视图同时清空默认引用。手动应用视图不写文章属性；重载只恢复显式默认视图，不覆写用户尚未保存的筛选草稿。

侧栏分组补充（D-0080，T-3234）：`ui-prefs.json` 增加 `libraryRailGroups`，键只允许 queues/sites/tags/aiTags，各为 `{collapsed:boolean,expanded:boolean}`，默认 false/false。组标题可收起整组，标题数量明确为分面项数；站点/标签超过8项默认显示前8项并提供全部/收束动作。当前选中项即使位于前8项之外仍可见且可移除，用户标签与 AI 标签保持各自命名空间。超过15项时提供组内文本过滤，关键词仅存当前组件会话，不保存查询或文章事实。偏好保存按组增量合并，互不覆盖其他组或阅读偏好；晚到的加载不覆盖已操作的组。

### 3.5.1 工作台就地预览（D-0082，T-3236）

桌面工作台/浮窗的列表点击可在同画布打开原生 Protyle preview；候选与已收录文章均可预览，打开/关闭不写阅读状态，也不进入阅读页签。首启确认候选通过浮窗会话参数直达首个扫描示例的inbox列表和预览，晚到的上次视图/默认保存视图不得覆盖此明确定位；只对本次窗口开启预览，不更改已保存开关。阅读器和预览共用 ProtyleHost：同文模式切换不重建，切文使用独立子宿主，销毁断开 resize 观察，旧异步正文不能填进新文宿主。初始化失败显示重试及原文入口，不自动把缓存正文当事实。

`ui-prefs.json` 增加 `workbenchPreviewEnabled:boolean`（默认 true；非法值回落默认）、`workbenchPreviewRatio:number`（默认0.45，只接受有限数，限制0.25–0.65，按扣除rail后的列表/预览可用宽度计算）。拖动及键盘调宽仅存比例，不存正在预览的文档ID、选区或正文。关闭窗格仅关闭本次文章；工具栏开关控制后续点击是否预览。窄Dock继续原文导航；移动库卡片点击使用全屏预览sheet，真实移动行为待B-0002。

已收录文章状态动作沿用 batchSetStatus/完成时间/打卡链；候选只提供确认收录、明确转本地、排除、补来源，先经统一收录/查重/手填保护，不把候选显示成 inbox 文章。写入成功后按本次可见列表顺序流向下一项；旧目标操作完成不能推进另一篇预览。摘录仅消费完整落在当前宿主中的合法块选区，经既有引述服务写原块之后，无锚点只能复制。选中项ID、推进顺序和来源输入草稿均为会话状态。大文档阈值与降级方式等待真实Protyle性能实测，不凭合成域层耗时切换渲染器。

### 3.5.2 筛选与行内动作密度（D-0083，T-3237）

桌面Dock/工作台/浮窗统一保留站点、用户标签、排序三项常用下拉；AI标签、收录来源、时间来源与内容载体放入“更多筛选”面板。筛选仍消费现有纯库投影，激活条件以可移除chip显示，用户标签与AI标签各有来源标识，丢失分面仍能清除；移动端保留已有草稿/应用sheet，同时显示已应用chip。展开状态仅会话有效，搜索/筛选不写文章事实。

桌面行表保留开始/继续阅读和标记已读两个高频入口，稍后读/归档/快照/AI富化/来源/多选移入显式溢出面板，归档行提供恢复。面板支持键盘、Esc与焦点返回，不以悬浮才显示作为唯一入口；操作仍复用现有真实状态/快照/富化服务。看板和窄Dock保留现有动作面，真实宿主验证后再决定是否统一收纳，不伪标评估完成。

查重补充（D-0084，T-3238）：3.8.6隔离E2E发现，刚写入的URL/status可在属性端点读到，但SQL文档IAL仍为写入前值，按IAL过滤会遗漏。统一查重入口增加当前插件派生索引的已知文档ID提示，逐条回读属性后才判同源，不把索引URL/状态当事实；随后仍取全SQL范围，已读ID去重。索引读取失败和已发属性读取失败拒绝判无冲突。未被本插件观察到的外部新增文档/并发写入仍受SQL发现延迟与内核无原子CAS的限制，不承诺跨客户端唯一约束；不能用固定等待替代属性核对。

### 3.6 阅读大纲（D-0073，T-3229）

只读查询当前文章 heading 块（思源原生 `type='h'`、`subtype='h1'`–`'h6'`），SQL sort/ID 仅作为稳定取全游标（每页最多500个），不作为正文次序；思源3.8.6会给多个标题相同 sort。按 D-0081/T-3235 使用隔离验证的 `/api/block/getChildBlocks {id}` 原生子块顺序遍历文档及非标题容器（数组项含 id/type/subType/content），标题不再次请求逻辑子块；最终 ID 必须与当前 root_id 的 SQL 标题资格集合一致。层级/标题变化、缺项、重复、循环或超过1000个容器请求/128层/50000节点时拒绝部分大纲并提供重试，未知结构中的未定位标题也不按 ID 猜顺序。此只读能力不继承事务写入授权。域层校验 ID/root_id/h1–h6；导航先定位页签节点，缺节点则打开原块，切文/卸载丢弃旧结果，不写文章状态。

### 3.7 属性 CSV 与脱敏诊断（D-0074，T-3232）

显式导出前完整对账，CSV 仅有效读库属性投影（不含正文、密钥、任意 IAL），用户/AI 标签分列，保留未知值并防公式注入。独立诊断 JSON 只含插件/协议版本、索引快照、数量、开关、前端类型与匿名阶段错误；不包含标题、路径、ID、URL、标签内容、模型地址/密钥或正文。导出失败拒绝，不能用旧缓存伪装当前结果；不新增文章属性或 saveData 文件。

### 3.16 本文单轮问答（D-0097，T-3250）

`ai.articleQuestionEnabled` 独立设置默认关闭，且受富化总开关、当前已保存通道、共享串行队列与每日调用额度约束。只对当前已有有效状态且非 internal/excluded 的文章执行；上下文为本文正文或用户明确选择的本文选区，问题至多1000码点，上下文至多16000码点。全文超限只传开头并在结果旁明确说明截断；选区必须能在当前正文中核对，且传入的块 ID 必须以 SQL `root_id` 精确归属当前文档，超限或归属不明拒绝；不夹带其他文章、图片字节或密钥。模型调用后再次核验选区块归属和文章属性/位置，变化则丢弃答案但保留已发生的用量计数。

模型输出 `{answer,evidence,insufficient}`，非“依据不足”结果至少包含一条可在本次上下文逐字核对的引文，拒绝虚构引文及非法输出。引文只是文本核对，不承诺事实判断正确。模型成功先记录调用消耗，解析/源文改变/关闭开关/离开页签仍计量；返回前重新核对根属性、位置和正文。结果只在本次页签显示，可复制，不写正文/摘要/作者/标签/状态，不创建对话历史或后续聊天。取消/切文不自动重发；备份恢复设置时此开关强制关闭。

### 3.17 旧来源 URL 兼容与周报文章清单（D-0098，T-3251）

`custom-clip-url` 只要是有效 `http://` 或 `https://`，即使旧文档缺少或带有未知 `custom-clip-content-type`，仍可显示来源网页动作；`local` 载体明确禁止从正文偶然链接推断来源。URL 的中文路径、百分号编码和查询参数不因显示判断而改写，非法协议仍显示缺来源。周报预览和 `weekly_digest` 共同使用可信 `custom-clip-done-time` 的统计期间，除数字外返回本周文章的确切文档 ID、标题、站点和完成时间；不以 `updated` 推算完成，也不把候选或 internal 文档列入清单。读库首屏可先显示派生 `glean-index.json` 缓存，随后必须完成全量三范围对账；同一插件实例的并发对账可合并，缓存不是真相源。

### 3.15 AI用量读取失败与写后核对（D-0096，T-3249）

用量记录缺失才按0初始化；读取失败、非法日期/计数或异常保存不能伪装成0。所有模型动作（含不限额模式）先验证用量可读取；成功调用后的递增必须写后读回，保存响应丢失但读回匹配时确认已计量，不自动重写。无法确认计量时当前插件实例停止后续模型调用，并在设置显示用量未知，已返回调用不自动重发；日志失败不解除停止状态。跨重载/多客户端计量仍无原子CAS，不承诺精确账单或恢复无法落盘的调用记录。

### 3.14 显式阅读书签（D-0095，T-3248）

用户在阅读页签明确“记住当前位置”才写入根属性reading-position，不以打开、滚动、失焦或关闭推断已读。书签定位当前正文宿主中的真实块及块内像素偏移；保留到归档/重读，不改五态、done-time或估算minutes，也不显示伪精确阅读百分比。schema校验版本/ID/整数偏移/时间，旧非法值只读保留、不自动清空。索引重建不创建或改写书签，JSON备份保留原始值，规范字段可经明确恢复；完整属性CSV包含该字段。

保存先核对文章资格/位置、预览中原始书签和块归属，写入点再次比较原始值，写后读回；同插件同文显式操作串行。其他设备已更新时拒绝旧草稿并提供重读，不自动覆盖；内核无CAS仍不保证跨客户端原子一致。恢复位置先回读根属性和块所属根ID；原块删除/移到别文、读取失败或宿主尚未渲染时明确降级打开原文/原块，不把缺失锚点替换为另一块。字号/行距变化后像素位置仅为近似，不承诺精确跨主题坐标。真实计时、自动断点和跨设备合并仍另立任务。

### 3.18 真实阅读计时（D-0121，T-3272）

`custom-clip-read-minutes` 只表示用户在阅读页签内实际停留的前台阅读分钟，与 `custom-clip-minutes` 的正文长度估算永久分开。计时只在阅读页签已挂载、窗口可见且获得焦点、正文宿主已渲染并属于当前文档时累计；`visibilitychange`、窗口 `blur`、切文、页签销毁或宿主不可用立即暂停，不监听滚动，也不从滚动位置推断进度。链接载体、正文缺失或宿主未渲染时不累计。

秒级余数只存在当前页签会话内；用户显式“标记已读”或“读完并下一篇”成功后，才把当前累计的完整分钟写入根属性。写回先读取当前属性、位置和原始 `custom-clip-read-minutes`，写入点再次核对并经 `clip-store` 写后读回；跨设备或其他窗口已改变时拒绝覆盖并提示重读。状态失败时不写真实分钟，真实分钟写入失败不回滚已成功的状态动作。备份和完整属性 CSV 原样保留该字段，索引只可选择性投影；不自动保存、不跨设备合并、不复用估算分钟。

### 3.13 AV单向状态投影与逐项结果（D-0094，T-3247）

显式挂库/刷新先完整对账当前有效非internal文章，文档根属性是唯一事实源；AV状态单元格变化不会反写文章五态。旧D-0012的反向表述无实现/实证，按本条修正。绑定数量以官方绑定ID→itemID映射读回为准，不以请求条数冒充成功；行号不是文档ID。每篇状态投影前回读资格，写后读取AV实际状态并再次核对文章状态；失败/未绑定/变化/结果未知分别返回，界面显示已绑定与实际对齐/失败数。失败可再次显式刷新，幂等复用已有行，不自动重发响应丢失的写入。列映射仍按当前已验证的命名契约，不承诺重命名记忆或未填列已经同步；源文章正文及属性不因挂库修改。

### 3.12 导入检查点与跨重载恢复（D-0093，T-3246）

`import-progress.json`为同工作区单导入任务的派生日志，只保存版本、源文件SHA-256指纹/格式、目标笔记本/目录、行身份及建文档/属性阶段、内核确切返回的文档ID；不缓存原始文件、正文或密钥，不作为文章属性事实源。开始建文档前必须保存创建意图，收到ID立即保存；意图之后无确切ID（重载、响应丢失或日志保存失败）标记结果未知，禁止自动另建或按标题认领。恢复须重新选择相同指纹/格式的源文件，并明确确认原目标配置；未完成任务须明确放弃记录后才能开始新任务，放弃不删除已建文档。

持有确切ID的恢复先核对根文档仍存在、位于原目标和当前来源相符且非internal；变化、移动或删除不创建替代。有效状态已存在时只同步索引，不改用户后续五态/完成时间/正文/tags/作者；仅半成品补缺，已填来源受保护且统一查重。暂停和弹窗关闭只阻止下一行，当前建文档/写属性动作可结束；已完成保留，进度/逐条失败/未知单独显示。单插件实例锁防止重入，日志读取/保存损坏失败必须就地反馈并停止，不静默覆盖；跨客户端无原子CAS仍保留。

### 3.11 批量富化任务与续跑（D-0092，T-3245）

多选已收录非internal文章后只读生成清单，列出会替换已有摘要/AI标签的篇数、共享额度及通道，用户明确确认才开始。逐篇读取最新资格/位置及预览涉及的原始摘要/AI标签/状态/来源，变化跳过；模型只走既有共享队列，写入仍经clip-store且写入点复查预期属性。源文章正文、五态、用户标签、作者及其他手填字段不由该任务改写。暂停/关闭只阻止下一篇，当前已发送动作可完成；已写不回滚。

`ai-batch.json`仅存版本/任务ID/日期、文档ID/尝试次数/派生执行结果，不存正文、摘要、标签内容、密钥或模型输出。每篇调用前先保存running检查点，保存失败不调用；结果保存失败立即停止，跨重载running转unknown且不自动重发。任务记录不是文章事实源，查看/恢复仍回读属性；恢复仅由用户明确选择pending或failed项，unknown须先查看原文并再次明确授权重跑，已成功项目默认不重跑。一个插件实例仅允许一个批量任务执行，两个窗口不会重复调用；跨客户端无原子锁仍保留。新预览不能覆盖未处理完的旧记录，只有用户明确放弃记录后才能开始新批次；放弃不撤销已写文章。

### 3.10 AI排队期间的设置更新（D-0091，T-3244）

运行中的插件实例已保存设置是队列执行时的配置来源；动作捕获的旧设置仅用于没有运行中设置的服务调用。排队后、正文读取后、额度读取后和调用模型前复查当前总模式/逐功能开关，并使用当前通道和额度。保存设置替换对象也必须生效，不能只检查旧引用；已发送的调用不承诺远端取消，成功仍记录用量。关开关后返回的结果不自动写文章属性或采纳为排版计划。

### 3.9 作者建议与制卡确认（D-0089/D-0090，T-3242/T-3243）

作者AI建议逐功能开关 `settings.ai.authorSuggestionEnabled` 默认关闭，富化总模式off时也不可调用。单篇显式请求复用共享串行队列/额度/通道，排队和读取后再次检查开关；成功模型调用先计量再解析。只发送当前文章的有界纯文本，不发送URL/资源/密钥；模型只能返回author和原文逐字证据，证据必须能在本次文本中定位并包含作者，空值/猜测/不匹配均拒绝。建议仅留当前编辑会话，显示AI来源/证据；采纳只填入可编辑草稿，最终显式保存仍走作者预期值校验和写后读回，不自动写属性或批改存量。

制卡从选区/摘录/命令进入统一可编辑预览，显示来源与正背面；取消预览不创建牌组/文档/块。确认后才创建卡片，空字段或超限不可提交；DOM文本必须转义。AI问句开关 `settings.ai.questionCardEnabled` 默认关闭，显式请求复用共享队列/额度/通道；结果填草稿，不自动提交。卡片是独立知识回流产物，不写源文章五态或手填属性。插入成功而riff登记失败保留确切卡块ID和牌组ID，当前预览重试只登记该ID，禁止再插入；响应丢失不得盲重发或猜测最近块。宿主同名文档不得因此被自动标记internal，真实多客户端并发仍不承诺原子唯一。

制卡分步恢复检查点保存为 `flashcard-recovery.json`，只记录版本、任务 ID、阶段、牌组 ID、宿主文档 ID、预分配卡片块 ID 和时间，不记录正文、引文、来源标题、模型输出、密钥或用户属性。插入前先保存 `insert-intent`；重载后只按该 ID 查询 `type='i'` 且 `root_id` 等于宿主文档的确切块，不能按标题、排序或“最近卡片”认领。已确认存在的卡片进入待登记路径，用户明确触发 `addRiffCards`；登记成功后记录 `registered` 再清理检查点。检查点损坏、读写失败、确切块不存在或登记结果未知均不自动重试，保留人工核对路径；内核登记接口的跨客户端原子性仍不承诺。

### 3.8 版本化元数据备份与恢复（D-0088，T-3241）

用户显式下载 `format=siyuan-glean-backup, version=1` JSON包，字段为 createdAt/pluginVersion/documents/settings/uiPrefs/index。完整对账后分批回读有效非internal文章根块的全部 `custom-clip-*` 原始字符串，documents含id/title/box/hpath/attrs；不含正文、资源、密钥值或用量/日志。用户tags和未确认候选只可能存在于index当次派生快照，不进入可恢复documents/字段；恢复绝不直接写入索引文件或用户tags。设置与界面偏好只导出规范化白名单。原始非法或未知clip属性可备份，不能以解析丢弃代替备份。

导入只读解析，文件≤20MiB、文章≤50000、单值≤1MiB；格式版本、ID重复、类型不符、缺有效状态或未知结构均拒绝。未知clip键或不能无损序列化的已知值会在逐字段预览标明不可恢复，不悄悄规范化或丢失。字段差异区分新增、替换、删除和不支持。默认仅选择可恢复的缺失字段；已有值/删除默认不选，必须逐字段明确选择，才允许经clip-store定点覆盖（含手填作者/URL/状态/优先级/评分）。

恢复仅作用于已存在的相同根块ID，不创建/替换正文，不映射标题相同的其他文档；缺失、internal目标、读失败分别列明并不可写。提交时复查预览中的当前位置和所选原始属性，变化拒绝；同插件同文明确编辑串行，写后读回核对。已写项目保留成功事实，失败/未知结果不自动重发，不宣称取消会回滚；再预览才能重新选择。最后从属性重新对账索引，失败显示已写数与索引未刷新状态，不以旧包索引遮盖失败。内核无原子CAS，跨客户端读写窗口仍保留限制。

恢复来源或补回状态前沿用统一URL查重；同来源冲突默认拒绝该文档的本次补丁，只有用户在该文档明确勾选“保留同来源另一份”后才允许。该选择只属于当前恢复预览，不进入偏好或备份。导入包不携带覆盖/确认授权，所有选择由当前会话重新产生。

设置与UI偏好恢复另需明确选择，预览比较当前保存值，应用前在插件实例的设置/偏好保存队列内复查；设置恢复强制关闭AI及协作写入开关、阅读默认只读，不自动调用模型或恢复密钥。属性恢复与偏好恢复各自反馈实际结果，不承诺整个包原子事务。未保存的设置草稿存在时禁用设置恢复；未知设置版本不可应用。读取保存数据失败拒绝备份/预览，不能把默认值伪装成真实快照。

### 3.4 排版整理预览与独立整理稿（D-0063，T-3219）

基础整理只缩短长 URL 的显示文字（目标不变）、合并普通段落间多余空行；导出正文中的代码、公式、表格、引用、列表、HTML、块属性和其他复杂结构不再修改。整理稿是 Markdown 阅读副本，不复制原文块 ID/原生 IAL；原文的块身份、属性和引用关系保留在原文。疑似广告/关注/下载文案、重复或无说明图片是清理候选，默认不选，只有用户勾选后才从整理稿移除；不删除原文或 assets。乱码仅检测提示，不猜测恢复已丢失内容。

本功能导出正文固定请求 `{id, yfm:false, addTitle:false, refMode:2}`，避免导出元数据/额外文档标题混入正文，并保留思源块链目标；不修改用户全局导出设置。可选字段已核对思源 v3.8.6 `kernel/api/export.go`、`kernel/model/export.go`，并在 `scripts/e2e/s1-flow.mjs` 用原始请求隔离验证。既有调用省略这些字段时仍沿用宿主默认。Markdown 导出会规范化原生超级块、IAL、嵌入等结构，不能把整理稿宣称为原生块无损副本。

AI 排版是显式动作，沿用既有通道、每日额度和日志，另设 `settings.ai.formattingEnabled` 功能开关，默认 `false`。输入为带稳定段落编号的普通文本和有限上下文；模型仅返回 JSON 结构计划（标题层级和清理候选编号），禁止生成替换正文、重排段落或操作保护块。整份计划校验通过后才能进入预览，超长文章明确降级为基础整理，不静默截断。模型调用成功计入共享额度，计划非法仍保留基础预览，日志不含正文或原始模型输出。

排版 AI 的图片边界（D-0076，T-3221）：prompt 中的图片块只发送固定 `[image]` 占位符，不发送图片 URL、alt、文件名、外链参数、图片字节或 base64；当前通道因此不具备图片语义判断能力。模型计划包含图片清理时拒绝该图片动作，不把文本模型输出当作视觉结论；重复、无说明和推广图片仍只能作为默认未选的人工候选，并且只影响独立整理稿，不删除原文或 assets。视觉模型、资源读取权限和多模态通道必须另行完成真实能力验证后才能扩展本契约。

原文、预览、选择和恢复令牌仅存本次弹窗内存，不落 saveData。显式确认后用既有 `createDocWithMd` 在原笔记本创建普通“阅读整理”文档，含原文回链及有效来源链接；通过 `clip-store.writeClip` 仅写既有 `custom-clip-internal=true`，不复制原文五态、URL、评分、优先级或标签。建文档前重新导出原文并复查标题、路径、笔记本和来源 URL，任何变化均阻止保存旧预览。建文档已成功而标记/索引失败时返回文档 ID，弹窗保留令牌并只重试标记/索引，不能重复建文档；请求响应丢失时不能认定未创建，提示先检查笔记本，禁止自动重试创建。首版不提供覆盖原文或全库批量整理。

## 4. 高亮块约定（消费批注插件产出，只读不编辑）

批注插件满足任一形态即可被聚合：
①文档内块引用/引述块带 `custom-clip-highlight` 属性；
②普通引述块（`>` 块）。
当前文档与全库摘录均为只读聚合（D-0064，T-3222）。全库范围先经 clip-store 对账，只包含有效读库状态的文章，排除候选、普通笔记和 internal 文档。沿用 SQL 端点，按最多 200 个根文档 ID 分批、每页最多 500 块，以块 ID 游标稳定分页；消费引述块或具有非空 `custom-clip-highlight` 的块，不把未标记子段落重复纳入。

搜索、站点、用户标签、AI 标签、排序、分页与多选是内存投影，不新增属性或 saveData。CSV/Markdown 导出只包含显式选择项和原块回链，CSV 防公式注入。导出前回读文章资格和块正文/归属，删除、权限错误或内容变化阻止旧导出。确认后创建 ordinary internal 文档；保留成功响应 ID，仅恢复标记/索引，创建结果未知禁止自动再建。

### 4.1 阅读回顾（D-0065，T-3223）

分布扩展（D-0086，T-3240）：期间作者计数与站点→作者二级计数只读取期间有可信完成时间文章的当前 author，不推断缺失署名；作者大小写/首尾空白归一，保留可见名称。每站点二级作者计数加“未记录作者”数应等于该站点总数。未记录站点的文章仍可计全局作者分布。候选和 internal 文档不进入这些计数。

质量补充：派生文章索引增加既有 internal 属性的只读投影，回顾入口排除显式 internal，即使该内部文档另有有效状态也不能混入阅读统计；不清除该文档原状态。完整对账/重建后更新投影，旧索引缺该投影时不凭标题猜测。

UI 默认 Top8，其余项汇总显示项数和计数之和，可展开查看全部；标签的计数之和是标签出现次数，不能当去重文章数。聚合只收纳展示，不截断数据；Markdown/CSV 报告保留完整作者、二级计数与缺失数，回顾 CSV 在末尾新增 author 列并沿用公式防护。展开状态仅组件会话内，不新增文章属性或 saveData。

周/月/年统计按本地日历和可信 `done-time` 汇总，归档后保留完成事实，不用 `updated` 推断。未知完成时间单独计数；完成时间只是最近一次显式完成，不能宣称完整重复阅读历史。年度热力图提供逐日等价文字，站点/用户标签/AI 标签分别统计。候选只作为独立待确认快照，不进入读库总量或完成数。报告/CSV 为当次已对账索引的投影，展示统计口径；Markdown 预览确认后创建 internal 文档，失败恢复遵循 §4 的文档 ID 规则，不新增文章字段。

### 5.1 宿主传输与外部失败响应（D-0061）

所有 JSON 与 multipart 请求都通过统一 `kernelPost` 校验思源响应；只有明确的数字 `code=0` 才算端点成功，缺响应、缺 code 或非零 code 必须拒绝。传输使用 SDK 的异步 Promise 接口 `fetchSyncPost`：`fetchPost` 经宿主 `processMessage` 处理非零响应时可能不调用成功回调，不能用成功回调包 Promise 等待失败。multipart 保留 FormData 原样，不设置 JSON Content-Type。已按思源 `v3.8.6` 的 `app/src/util/fetch.ts` 与 `kernel/apicontract/inbox.go` 核实，不新增端点。

收集箱列表还须校验云服务内层 `code=0` 和列表结构；外层成功不能掩盖内层失败。列表/详情异常分别返回不可用/null，云端删除和 assets 写入异常则抛出，让服务保留云条目或旧快照。当前不新增写入请求超时后的自动重试：响应丢失时不能据此认定服务器未写入。

收集箱迁入使用 `inbox-recovery.json` 记录 `creating`、`capture-pending`、`remove-pending` 或 `unknown` 阶段、云端 `oId`、目标笔记本/路径和确切文档 ID；不记录正文、标题、URL、标签或属性。创建前先保存 `creating`，收到合法文档 ID 后立即保存 `capture-pending`；属性/索引失败只重试该 ID，云端删除失败只重试 `removeShorthands`。创建响应丢失、非法 ID 或检查点读写失败进入未知/人工核对路径，禁止按标题、路径或最近文档认领，也禁止自动重建。同一检查点只能由当前云端 `oId` 继续，完成云端删除后才清理。

### 5.2 AI 辅助范围与共享额度（D-0067，T-3225）

富化、排版、阅读总结和翻译共享同一串行队列；额度检查在队列执行时进行，避免并发绕过每日上限。模型已经成功返回即记录调用消耗，后续解析/属性写入失败不退回调用额度，调用前关闭、空文本或无额度不请求模型。阅读动作不在队列中二次排队。语义查重/相关旧文只消费经 clip-store 确认的有效非 internal 文章，不能把普通笔记或候选作为已收录建议；相关旧文由调用上下文传入当前设置，关闭模式或 relatedWhileReading=false 禁止查询。

AI 设置遵循逐功能默认关闭（D-0070，T-3228）：新用户的 dedupOnEnrich、relatedWhileReading、presetActions、formattingEnabled 均为 false，富化模式仍默认 manual。旧设置中显式保存的布尔 true/false 保留，字符串/数字等非法开关回退默认关闭，旧 enrichOnCapture 三态兼容不自动开启其他功能。额度文案明确包含富化/总结/翻译/排版，成功模型调用计数与结果是否可用分开。

### 5.3 原文事务研究仅限隔离 spike（D-0075，T-3220）

本节记录 `scripts/spike/transaction-spike.mjs` 在思源 `3.8.6` 隔离工作区的实证，不构成生产 API 封装，也不授权排版功能写原文。探针确认：`/api/block/getBlockDOM` 的返回数据含 `dom`，`/api/block/getBlockKramdown` 的返回数据含 `kramdown`；`/api/block/updateBlock` 接受 `{id,data,dataType}`，本次普通叶段落更新保留文档块 ID 和根块属性，但 `undoState` 的 `canUndo/canRedo` 未改变。

带 `undoOperations` 的 `/api/transactions` 请求形状为 `{reqId,app,session,transactions:[{doOperations,undoOperations}]}`。探针在含嵌套列表、代码、公式、表格、图片引用、块引用和跨文档块引用的复杂文档中只更新一个普通叶段落，读回确认复杂文档块 ID 集合、根属性、叶块用户 IAL 和跨文档引用保持；`/api/transactions/undo` 和 `/api/transactions/redo` 使用 `{rootID,app,session}`，可完成本次变更的撤销/重做往返。`undoState` 只提供文档栈状态及 `peekMutatedRootIDs`，没有插件或操作唯一标识。跨两个 session 的样本表明，撤销仍作用于该文档栈顶，不能据 session 判定“属于本插件”。

同一事务包含一个有效叶块更新和一个不存在块更新的样本中，外层响应为 `code=0`，实际读回没有首个更新；这只证明该样本的内核执行没有留下部分更新，不外推为跨请求或所有操作类型的 ACID 保证。双编辑器、用户中间编辑和真实宿主撤销尚未证实；产品不开放原文块级排版、独立“撤销本插件操作”按钮，也不把 `updateBlock` 当作可撤销事务。

同一 HTTP 请求内放入两个独立 Transaction 的对照中，第一个有效叶块更新已落盘，第二个不存在块更新未落盘，外层仍为 `code=0`。因此请求中的多个 Transaction 不是一个原子单元；若未来需要多块原文变更，必须在一个经验证的事务内完成并逐块读回，不能依靠请求数组或多次 `updateBlock` 获得整体提交/撤销语义。

探针还在含嵌套列表的隔离文档中更新一个列表容器，读回确认 11 个块的 ID 集合、父子/前后邻接和用户 IAL 保持，且该容器事务可撤销/重做；邻接通过 `/api/block/getBlockSiblingID` 读取，不能从 `blocks` SQL 表臆造 `previous_id/next_id` 列。后续同一隔离工作区补测了块接口与受支持事务的边界：`/api/block/insertBlock` 和 `/api/block/deleteBlock` 各自返回操作数据，但返回操作的 `rootID` 为空，直接调用后的 `undoState.canUndo/canRedo` 与调用前相同；将它们的原生操作放进单个 `/api/transactions` 并提供对应的插入/删除逆操作后，插入、删除均可撤销/重做且既有块 ID 保持。`/api/block/getHeadingLevelTransaction` 对已有标题从 `h1` 调整到 `h3` 的事务可保留标题块 ID 和用户 IAL 并撤销/重做；普通段落请求该端点返回空事务，不能据此实现段落转标题。

新增的简单重排与引用资源样本中，`/api/block/moveBlock` 可改变同级邻接并保留块 ID、根属性，但直接调用不改变 undo/redo 栈；恢复到原邻接后 ID 集合仍一致。含本地 PNG、块引用和 `NodeBlockQueryEmbed` 的文档通过 `/api/asset/getDocImageAssets`、`getDocAssets`、`statAsset` 和 `getBlockDOMWithEmbed` 读回；对其中一个普通叶块提交事务并 undo/redo 后，资源集合、嵌入目标块 ID 和文档块 ID 集合均保持。以上仍只覆盖当前 `3.8.6` 和隔离服务 API，不证明复杂容器重排、资源变更、双编辑器并发、响应丢失、重启或真实宿主撤销可以安全执行。

同一隔离工作区最后重启内核后，事务已经写入的普通叶块正文和文档块 ID 集合仍保持；内核内存中的 undo/redo 历史清空。重启后的读回通过后再用非撤销的 `updateBlock` 清理探针标记。该结果不证明用户重启前后可继续使用插件专属撤销，也不覆盖双编辑器、并发和响应丢失。

响应丢失探针通过只丢弃客户端 HTTP 响应的回环代理，将 `/api/transactions` 请求完整转发并等待服务端响应后销毁客户端响应。客户端观察到传输失败，但随后读回确认事务已经落盘、块 ID 未变，文档 `undoState` 可确认存在历史；探针只执行一次请求并用文档根 ID 撤销，不自动重发。该结果只证明响应丢失时必须先核对状态，不能把网络异常当作未写入或安全重试。

最新隔离样本使用同一回环内核上的两个独立 API 客户端并发提交事务：更新不同叶块时两次写入均可读回，块 ID 和根属性保持，分别撤销/重做可往返；更新同一叶块时两个事务基于同一旧 DOM，最终读回只保留一个客户端标记（本次样本为客户端 B），因此没有 CAS 或冲突合并保证，必须先读回再决定，不可自动重发。该样本只证明服务 API 的并发边界，不证明双 Protyle 编辑器、用户中间编辑或真实网络行为。

嵌套列表项跨 NodeList 移动/恢复已在源列表保留另一项的样本中验证：ID/根属性/用户IAL和恢复后的原生父级/前后邻接保持，深层子树样本包含 5 个块并保持内部关系，直接moveBlock不进undo。另一个合法样本将唯一源列表项移入目标列表后确认列表项 ID 保持、源空列表从索引消失；对已删除列表调用 `getBlockDOM` 得到 `code=0` 空内容，因此删除后读回必须同时检查内容，不能只看 code。SQL parent_id可能是章节标题，getBlockSiblingID对列表跳过NodeList；探针分别保留这两种投影，并从任务专属 `.sy` 校验真实关系，不覆写字段或把投影用于猜测恢复锚点。该证据不包括复杂容器撤销、双 Protyle、用户中间编辑、资源权限/删除或真实宿主撤销。

资源边界样本使用真实1×1PNG，经putFile写入/另一PNG覆盖/恢复原字节后逐次getFile读回一致；两个笔记本的文档引用同一资源均由getDocAssets列出。旧版纯文本伪PNG样本只算普通文件字节证据。当前不提供笔记本/用户权限隔离、外链、删除或编辑器渲染结论，也不把资源写入纳入文档事务undo。

## 6. 对外协议 v1（D-0066，T-3224）

`window.siyuanGlean = { version, listClips(filter), getClip(id), setClipStatus(id, status) }`。
`apiVersion:1`，`version` 为插件版本。listClips 对账后只返回已确认读库属性投影，支持状态/站点/用户标签/AI 标签/关键词及稳定 ID 排序，limit 为 1–200、offset 为非负整数。getClip 校验 ID，不存在、internal、候选返回 null，连接/权限失败抛真实错误。返回值深度脱离内部引用，不返回正文、密钥或任意属性写接口。

## 7. 隔离测试与验收账本（D-0112，T-3264）

这是开发工具的文件契约，不属于文章属性、插件设置或对外桥。M0/AV spike 每次创建独立系统临时工作区、动态回环端口与专属标记；结果默认保存在本次工作区，包含工作区、端口、内核/插件版本和逐项 `{name,ok,detail}`，不覆盖仓库历史结果。可用 `--results <path>` 指定证据输出，日志/结果不含密钥。

跨插件 E2E 会话 manifest 版本保持 `1`：`createdBy` 使用通用 `siyuan-plugin-e2e-session`，并记录 `pluginName`、`pluginVersion` 和 `pluginDir`；`pluginName` 必须来自目标 `plugin.json`，复制目标必须是该插件的 `dist`。停止器按 manifest 的工作区标记、回环地址、PID 和插件身份核验后操作。旧版 `siyuan-glean-e2e-session` manifest 只读兼容，不再生成；不同插件不得共用工作区、端口、manifest 或停止命令。

验收账本版本保持 1，新增只追加的 `checks` 记录逐项编号、结果、证据路径与 SHA-256。旧活动账本缺少 `checks` 时按尚未验收处理。`link` 只关联运行环境，ready manifest 不是验收结果；`report` 仅向隔离内核会话导入有明确逐项布尔结果及匹配工作区的 spike 报告。`passed` 必须有逐项验收结果、最新结果全部通过、证据文件存在且哈希未变，以及该类别的设备/宿主确认；有未解决失败项时拒绝关闭。关闭记录不可重开或修改，复测新建会话。并发修改使用会话专属锁，冲突拒绝而不丢记录。

后台停止先核对 manifest 的版本、正整数 PID、回环 host/port/base 一致性及工作区标记。两进程都已退出时只收口元数据，不向旧端口发请求；活跃会话使用已有内核退出端点，并等待内核与启动进程都结束后才记 stopped。不得依进程名称清理任何作者实例。

事务探针的 `transaction-report.json` 另有 `reportVersion`，并记录 `workspace`、回环 `host`/`port`、`kernelVersion`、`pluginVersion`、逐项 `{name,ok,detail}` 的 `results`、详细 `probes` 和 `limitations`。只有实际读回通过的隔离证据进入 `results`；负面观察和未验证边界留在详情中。验收账本可导入该报告，但报告不改变 T-3220 的真实宿主、权限、资源删除或编辑器待办状态。
