# RESEARCH — 物理删除回收期研究（T-1905）

> 目的：归档生命周期组（T-1866–T-1879）中"删除（含文章一起删除）"是否提供待删除隔离区/撤销期限，或坚持不可逆时的补偿措施。
> 结论日期：2026-10-01。研究方式：竞品模式分析（Raindrop Trash）+ 思源内核数据历史能力 + 本插件现状。

## 1. 现状（本插件）

- 插件**当前没有任何物理删除功能**：删除文档从未出现在任何动作中（五态流转只有 archived）。
- T-1866（归档后处理入口）要求提供"保留原位置 / 删除文章 / 移入【归档】文档"三选项——物理删除是**待实现**能力，尚未进入契约。
- T-1867（P0 契约）与 T-1868（P0 spike）分别要求先修订契约与内核端点实证——**未完成前不得实现删除**。

## 2. 竞品模式（Raindrop Trash）

- Raindrop：删除 → Trash 保留（默认永久保留，可手动清空）→ 可恢复。
- 关键差异：Raindrop 是云服务自持存储；本插件**无自持存储**——文章正文在思源文档中，删除由内核执行。

## 3. 思源内核能力

- 内核 `removeDoc` 为物理删除，但思源自带**数据历史/文件历史**（`.siyuan/history`），已删文档在历史中可人工找回（有保留期限，随清理策略滚动丢失）。
- 内核**无公开的回收站/可恢复删除 API**——插件层做"可恢复删除"只能靠自建（移动到隔离文档而非真删）。

## 4. 裁决建议（供 T-1866/T-1867 契约讨论）

| 方案 | 说明 | 建议 |
|---|---|---|
| A. 直接删除 + 二次确认 | 确认框列标题/路径/不可逆提示；依赖思源数据历史兜底 | 最小实现，作为"确认足够明确"的底线 |
| B. 移入【回收】隔离文档 | "删除" = 移动到笔记本下【回收】宿主（可随时人工清理）；真删除留给用户在思源内手动做 | **推荐**：可恢复、零后台、与 T-1869【归档】宿主模式同构 |
| C. 定时自动清理 | 回收期满自动真删 | **不采用**：后台定时删除违反平静原则（D-0008 同源） |

- 推荐 **B 为默认 + A 不可逆确认作为「彻底删除」二级动作**；"回收期"不设自动期限（无后台），仅提示用户【回收】宿主可手动清理。
- 数据主权：B 方案下文章仍在思源文档树（属性随文档移动保留），与 T-1873 数据主权抽查兼容。

## 5. 相关任务

- 实现：T-1869（【归档】宿主幂等创建）、T-1870（归档移动语义）、T-1871（删除安全语义）
- 验收：T-1873（删除/移动前后数据主权抽查）、T-1874/T-1875（单篇/批量归档选项矩阵）
