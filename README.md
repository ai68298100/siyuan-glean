# 小驴拾遗 (Lv Glean)

> **把吃灰的收藏捡回来喂给自己。**
> *Glean your clippings before they gather dust.*

小驴拾遗管理已经存进思源的剪藏文章，把它们变成一份可以确认、分拣、阅读和回顾的读库。它不是 RSS 订阅器，也不会替你抓取网页；普通笔记不会因为放在读库笔记本里就自动入库，打开文档也不会被推断为读完。

插件的最短闭环是：**发现来源证据 → 预览候选 → 用户确认收录 → 分拣 → 开始阅读 → 明确标记已读 → 日后回顾**。文章状态写在文档属性上，卸载插件不会删除这些状态。

[English](README.en-US.md)

## 它解决什么问题

思源官方剪藏扩展保存文章很方便，但来源 URL 和时间通常只是正文模板中的文本，搜索、数据库和查询无法直接按文章管理。小驴拾遗用 `custom-clip-*` 文档属性补上可查询的文章元数据，并用可重建索引提供面板视图。

扫描范围只决定去哪里找，不代表范围里的每篇文档都是文章。候选必须有有效来源 URL、精确的 `#剪藏` 标签或官方模板来源行等证据；候选会展示出现原因和缺失项。用户确认单篇候选或存量迁移报告后，文章才进入五态读库。

## 当前能力

### 收录、迁移与读库

- **五态队列**：收件池 `inbox`、稍后读 `later`、阅读中 `reading`、已读 `done`、归档 `archived`。
- **统一收录入口**：候选面板、编辑器右键“加入读库”、命令面板、思源收集箱和外部导入都写入同一套属性规则。
- **先预览再迁移**：存量整理先做 dry-run 报告，再逐批回填；支持保存进度、暂停和恢复，不覆盖已有的 URL、状态、优先级和评分。
- **候选处理**：可补来源链接、明确作为本地文档收录，或排除误报。候选不计入收件池数量、每日重浮和阅读统计。
- **正文载体**：面板卡片标示全文剪藏、仅链接和用户明确指定的本地文档；缺少字数、时长或可信时间时显示未知。统一载体徽章和打开策略已接入：全文优先打开思源正文，仅链接在有效来源 URL 下打开原文，本地/未知载体不显示网页动作（移动端真机验收见 B-0002）。
- **读库视图**：Dock、工作台和看板共享文档属性状态，支持标题/站点/用户标签/来源/时间来源/载体筛选、排序、批量改状态、快照和索引重建。三画布目视一致性和移动端操作仍待 B-0002。

### 阅读与抗吃灰

- **开始阅读**：把文章设为 `reading` 并按载体打开正文或来源；全文剪藏在思源原生编辑器外显示低干扰上下文（标题、载体、来源、状态和动作）。仅链接缺来源时明确提示，不伪称已打开原文。
- **标记已读**：只有用户明确执行“标记已读”才进入 `done`，可选的打卡桥也在这个动作上触发。
- **今日拾遗**：从未完成文章中挑选少量条目，附“为什么出现”的事实说明（吃灰天数、优先级、来源、近期未读主题）；提供开始阅读、改天和归档，改天幂等且只影响当天展示，不伪装成完成。挑选基于打开面板时对账后的真实属性。
- **队列提醒与超龄归档**：收件池超量提示；超龄文章先展开候选清单供逐篇勾选，确认后只归档勾选篇目并反馈真实成功数。

### 可选 AI 与承接能力

- **AI 富化**：手动或显式开启自动的一句话摘要、AI 标签和语义相似提醒；默认模式为手动，不自动消耗 token。AI 标签与用户标签分开保存。
- **阅读辅助**：思源 AI 预置动作可用于总结、要点和反方观点；相关旧文、翻译和成本提示仍按 T-1718 逐项验收。
- **统计与周报**：提供文章、字数、站点和标签统计，并可生成 Markdown 周报。“本周完成”只统计有可信完成时间的文章（显式标记已读或导入文件的已读时间）；旧数据没有完成时间时不伪造数字。重浮与超龄归档已基于对账后的真实属性投影（T-1710）。
- **可选承接**：读库数据库投影、思源收集箱迁入、Pocket/Omnivore/wallabag 导入、剪藏文档 HTML 快照、摘录制卡、智能体工具和小驴打卡桥已有代码入口；真实导出文件、真机和外部服务联调见 [docs/BLOCKERS.md](docs/BLOCKERS.md)。

## 第一次整理剪藏库

1. 安装并启用插件，在设置中选择一个或多个剪藏笔记本作为**读库笔记本**。已有的 `#剪藏` 文档也可作为候选来源被扫描。
2. 打开读库面板，点击 **整理剪藏库**，先执行 **先看报告（不写入）**。
3. 按候选证据核对文章：补有效来源 URL、选择作为本地文档收录，或排除误报。没有明确来源的普通笔记不会被批量收录。
4. 确认报告后开始分批回填。已能确定的 URL、正文类型、字数、时间来源等会写入属性；无法确定的字段保持未知。
5. 回到读库，把文章分到稍后读、开始阅读或归档。读完后明确点击 **标记已读**。

之后的新文章也可以从候选卡逐篇确认，或在文档右键菜单中选择“加入读库”。外部导入通常只有来源链接，界面会将它与全文剪藏区分开。

## 数据、隐私与边界

- 所有文章状态和元数据以文档属性为事实源；插件 `saveData` 保存派生索引、迁移进度、偏好设置和 AI 用量/日志等辅助数据，均不充当文章状态的事实源。
- 插件不覆盖用户已经填写的 URL、状态、优先级和评分；用户明确改状态时才执行状态覆盖。
- AI 默认使用你配置的思源模型；也可选择拾遗专用 OpenAI 兼容通道。插件不内置 API key，不要求账号订阅。启用自定义通道后，文章内容会随提示发送到你填写的 endpoint，请按该服务的隐私政策使用；AI 失败时阅读主流程仍可继续。
- 插件不提供 RSS 订阅、云端账号同步、社交集合、付费墙或自动代读。已吸收 Folo/RSS 的统一时间线、载体标识和来源引导；可关闭的 AI 阅读辅助按 T-1718 逐项验收，边界记录在 [docs/RESEARCH-folo.md](docs/RESEARCH-folo.md)。
- 支持思源 **v3.8.5+**。桌面、移动和浏览器主链分别验收；官方扩展实剪、真实 AI、收集箱、外部导入及真机 UI 的状态见 [docs/BLOCKERS.md](docs/BLOCKERS.md)。

“代码已有入口”不等于“所有平台都已验收”。主链完整隔离 E2E、作者桌面走查、移动/浏览器冒烟和发布门禁由 T-1713 追踪；在此之前不把插件描述成已经完成全部平台验证。
