# 小驴拾遗 (Lv Glean)

> **把吃灰的收藏捡回来喂给自己。**
> *Glean your clippings before they gather dust.*

小驴拾遗管理已经存进思源的剪藏文章，把它们变成一份可以确认、分拣、阅读和回顾的读库。它不是 RSS 订阅器，也不会替你抓取网页；普通笔记不会因为放在读库笔记本里就自动入库，打开文档也不会被推断为读完。

插件的最短闭环是：**发现来源证据 → 预览候选 → 用户确认收录 → 分拣 → 开始阅读 → 明确标记已读 → 日后回顾**。文章状态写在文档属性上，卸载插件不会删除这些状态。

## 它解决什么问题

思源官方剪藏扩展保存文章很方便，但来源 URL 和时间通常只是正文模板中的文本，搜索、数据库和查询无法直接按文章管理。小驴拾遗用 `custom-clip-*` 文档属性补上可查询的文章元数据，并用可重建索引提供面板视图。

扫描范围只决定去哪里找，不代表范围里的每篇文档都是文章。候选必须有有效来源 URL、精确的 `#剪藏` 标签或官方模板来源行等证据；候选会展示出现原因和缺失项。用户确认单篇候选或存量迁移报告后，文章才进入五态读库。

## 当前能力

桌面工作台和浮窗的列表支持就地预览：点击文章或候选即可核对正文与来源，打开不会改变阅读状态。可在预览中确认收录、补链接、排除误报、分拣或摘录；成功处理后继续当前列表。分隔条支持拖动和键盘，顶部“就地预览”可关闭此点击行为；窄侧栏继续打开原文，移动端使用全屏预览。筛选栏保留三项常用下拉，其他条件放在“更多筛选”，已应用条件可逐项移除；行表低频动作集中在“更多操作”。真实宿主和移动体验仍待[阅读器验收](docs/READER-ACCEPTANCE.md)。

### 收录、迁移与读库

来源作者可记录公众号、频道或专栏名。列表“更多操作”、文章预览和阅读伴生栏提供“编辑作者”；已有署名受保护，清空需明确保存，属性变化时保留草稿供核对。点击作者可查看其全部五态文章，作者筛选和保存视图独立于站点/标签，CSV包含作者列。回顾支持站点→作者钻取和Top8/其他分布，缺失署名单列；官方扩展目前不能仅靠模板自动抓公众号，见[能力研究](docs/CLIPPER-AUTHOR-RESEARCH.md)。AI批量推断及真实存量回填仍待开发/验收。

- **五态队列**：收件池 `inbox`、稍后读 `later`、阅读中 `reading`、已读 `done`、归档 `archived`。
- **统一收录入口**：候选面板、编辑器右键“加入读库”、命令面板、思源收集箱和外部导入都走同一套属性规则；收集箱和外部导入的真实服务前提见能力矩阵。
- **先预览再迁移**：存量整理先做 dry-run 报告，再逐批回填；支持保存进度、暂停和恢复，不覆盖已有的 URL、状态、优先级和评分。
- **候选处理**：可补来源链接、明确作为本地文档收录，或排除误报。候选不计入收件池数量、每日重浮和阅读统计。
- **正文载体**：面板卡片标示全文剪藏、仅链接和用户明确指定的本地文档；缺少字数、时长或可信时间时显示未知。统一载体徽章和打开策略已接入：全文优先打开思源正文，仅链接在有效来源 URL 下打开原文，本地/未知载体不显示网页动作（移动端真机验收见 B-0002）。
- **读库视图**：Dock、工作台和看板共享文档属性状态，支持标题/站点/用户标签/来源/时间来源/载体筛选、排序、批量改状态、快照和索引重建。快照需要思源导出和 assets 写入；可在设置中开启收录后自动生成，失败时保留已完成收录并可手动重试。三画布目视一致性和移动端操作仍待 B-0002。

### 阅读与抗吃灰

- **排版优化**：阅读上下文和阅读页签提供长链接显示缩短、空行整理、可选推广/图片清理和乱码提示；原文对照后保存独立“阅读整理”稿，保留原文及来源回链。AI 一键排版默认关闭，需配置通道并手动开启，只给结构计划、共享每日额度。当前只发送文章文本，不发送图片字节或外链图片；图片候选只表示结构证据，不代表视觉语义判断。宿主显示与真实模型仍待验收，边界见 [排版说明](docs/FORMATTING.md)。

- **开始阅读**：把文章设为 `reading` 并按载体打开正文或来源；全文剪藏在思源原生编辑器外显示低干扰上下文（标题、载体、来源、状态和动作）。仅链接缺来源时明确提示，不伪称已打开原文。
- **标记已读**：只有用户明确执行“标记已读”才进入 `done`；打卡桥需用户开启、安装并启用小驴打卡且选定目标，桥接失败不阻断已读状态。
- **内嵌阅读页签（实验，默认关）**：在设置开启后，“开始阅读”会把思源编辑器嵌入插件页签打开——左侧正文（默认只读预览，可显式切到编辑，改动直接保存到思源），右侧伴生栏提供状态动作、优先级评分、正文诊断、原文与快照入口。数据仍全部走思源内核，不复制正文。
- **今日拾遗**：从未完成文章中挑选少量条目，附“为什么出现”的事实说明（吃灰天数、优先级、来源、近期未读主题）；提供开始阅读、改天和归档，改天幂等且只影响当天展示，不伪装成完成。挑选基于打开面板时对账后的真实属性。
- **队列提醒与超龄归档**：收件池超量提示；超龄文章先展开候选清单供逐篇勾选，确认后只归档勾选篇目并反馈真实成功数。

### 可选 AI 与承接能力

- **AI 富化**：手动或显式开启自动的一句话摘要、AI 标签和语义相似提醒；默认模式为手动，不自动消耗 token。需要配置思源模型或拾遗专用通道；没有模型、额度耗尽或调用失败时跳过并留日志，AI 标签与用户标签分开保存。
- **阅读辅助**：思源 AI 预置动作可用于总结、要点和反方观点；相关旧文、翻译和成本提示仍按 T-1718 逐项验收。
- **全库摘录**：在摘录页切换当前文档或全库，按关键词、站点、用户标签和 AI 标签查找引述块；多选复制、CSV 或预览后保存 Markdown，保留原块回链。导出前核对源块，变化或删除时保留选择并阻止旧导出，见 [摘录说明](docs/HIGHLIGHTS.md)。真实宿主交互仍待验收。
- **阅读回顾**：按周/月/年查看可信完成时间、年度热力图和独立的用户/AI 标签统计，预览后生成 Markdown 报告或导出 CSV。归档保留完成事实；没有完成时间时单列未知，候选只作为当前快照，见 [统计口径](docs/READING-REVIEW.md)。真实宿主显示仍待验收。
- **对外桥接 v1**：其他插件可读取已确认文章的属性投影；状态写入默认关闭，开启后也只允许五态修改，卸载使旧引用失效，见 [桥接协议](docs/BRIDGE.md)。双插件真实联调仍待验收。
- **可选承接**：读库数据库投影、思源收集箱迁入、Pocket/Omnivore/wallabag 导入、剪藏文档 HTML 快照、摘录制卡、智能体工具和小驴打卡桥已有代码入口；它们的前置条件、隔离证据、失败降级和真实验收状态见[能力矩阵](docs/CAPABILITY-MATRIX.md)与 [docs/BLOCKERS.md](docs/BLOCKERS.md)。

## 第一次整理剪藏库

1. 安装并启用插件，在设置中选择一个或多个剪藏笔记本作为**读库笔记本**。已有的 `#剪藏` 文档也可作为候选来源被扫描。
2. 打开读库面板，点击 **整理剪藏库**，先执行 **先看报告（不写入）**。
3. 按候选证据核对文章：补有效来源 URL、选择作为本地文档收录，或排除误报。没有明确来源的普通笔记不会被批量收录。
4. 确认报告后开始分批回填。已能确定的 URL、正文类型、字数、时间来源等会写入属性；无法确定的字段保持未知。
5. 回到读库，把文章分到稍后读、开始阅读或归档。读完后明确点击 **标记已读**。

之后的新文章也可以从候选卡逐篇确认，或在文档右键菜单中选择“加入读库”。外部导入通常只有来源链接，界面会将它与全文剪藏区分开。

## 数据、隐私与边界

- 所有文章状态和元数据以文档属性为事实源；插件 `saveData` 保存派生索引、迁移进度、偏好设置和 AI 用量/日志等辅助数据，均不充当文章状态的事实源。
- 插件不自动覆盖用户已经填写的 URL、状态、优先级、评分和作者；明确的状态/作者编辑动作才允许定点覆盖。
- AI 默认使用你配置的思源模型；也可选择拾遗专用 OpenAI 兼容通道。插件不内置 API key，不要求账号订阅。启用自定义通道后，文章内容会随提示发送到你填写的 endpoint，请按该服务的隐私政策使用；未配置模型、浏览器直连受限或 AI 失败时会跳过，阅读主流程仍可继续。
- AI 排版当前只把文章文本发送到已选通道，不读取、下载或发送图片字节，也不把图片 URL 当作视觉输入；需要视觉图片判断时仍须等待独立的通道能力、资源授权和真实模型验收。
- 插件不提供 RSS 订阅、云端账号同步、社交集合、付费墙或自动代读。已吸收 Folo/RSS 的统一时间线、载体标识和来源引导；可关闭的 AI 阅读辅助按 T-1718 逐项验收，边界记录在 [docs/RESEARCH-folo.md](docs/RESEARCH-folo.md)。
- 清单声明支持思源 **v3.8.5+**，但桌面、移动和浏览器的真实 UI 仍须分别验收；官方扩展实剪、真实 AI、收集箱、外部导入及真机 UI 的状态见[能力矩阵](docs/CAPABILITY-MATRIX.md)与 [docs/BLOCKERS.md](docs/BLOCKERS.md)。

“代码已有入口”不等于“所有平台都已验收”。主链完整隔离 E2E、作者桌面走查、移动/浏览器冒烟和发布门禁由 T-1713 追踪；在此之前不把插件描述成已经完成全部平台验证。
